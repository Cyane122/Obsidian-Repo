> Low-Level Vision은 밝기·대비·노이즈·경계 등 image의 시각적 품질을 다룬다. 이번 자료는 haze type을 먼저 분류해 specialized dehazer를 선택하는 HazeSpace2M framework와, Wavelet·Diffusion·Transformer를 결합하는 TriFuse를 설명한다. Enhancement의 목적은 보기 좋은 image를 만드는 데서 끝나지 않으며, 복원된 image가 Object Detection 같은 downstream task에 유용한지도 별도로 평가해야 한다.

## Low-Level Vision과 Image Enhancement

Low-Level Vision은 image의 pixel과 local structure에 가까운 수준에서 입력을 복원하거나 개선하는 작업이다. Haze로 낮아진 contrast를 회복하는 Dehazing과 어두운 image를 개선하는 Low-Light Image Enhancement(LLIE)가 이번 강의의 중심이다.

Downstream Recognition은 image에 어떤 object가 있는지, 어디에 있는지, 어떤 상황인지를 해석한다. Object Detection은 class와 bounding box를 예측하므로, 출력 자체가 enhanced image인 LLIE와 구분된다.

| 작업 | 입력의 문제 | 주요 출력 | 평가 관점 |
| --- | --- | --- | --- |
| Dehazing | fog·environmental haze·cloud에 의한 시야 저하 | haze가 감소한 image | reference와의 유사성, 구조·색상 보존 |
| LLIE | 부족한 조명과 낮은 가시성 | 밝기와 detail이 개선된 image | 밝기, noise, 구조, 지각적 품질 |
| Object Detection | object의 위치와 class를 알아야 함 | bounding box와 class | detection 성능 |

Image Enhancement와 Recognition은 연결되지만 목적 함수가 같다거나 성능이 항상 함께 좋아지는 것은 아니다. 전체 brightness만 높이면 object가 잘 보일 수 있지만 noise도 커질 수 있고, 강한 sharpening은 경계 주변에 artifact를 만들 수 있다.

따라서 enhancement 결과는 image quality와 downstream utility라는 두 관점에서 해석한다. 강의에서 도로 scene을 사용하는 이유도 열화된 입력이 navigation과 detection에 영향을 주기 때문이다. *(슬라이드 3–4, 15, 21)*

### Single Image와 Multimodal의 구분

이번 두 연구는 기본적으로 하나의 image를 개선하는 문제를 다룬다. Single RGB image를 frequency band로 나누거나 여러 Neural Network를 결합해도 입력 modality가 추가되는 것은 아니다.

Transformer, Diffusion, Wavelet을 함께 쓴다는 것은 서로 다른 처리 방식을 결합한다는 뜻이다. Camera와 다른 sensor를 결합하는 Multimodal Fusion과는 구분해야 한다.

## HazeSpace2M Dataset

HazeSpace2M은 다양한 scene과 haze condition에서 Single Image Dehazing을 연구하기 위한 dataset이다. 특정한 haze type이나 synthetic condition에 치우친 기존 설정을 넓히는 것이 자료에서 제시한 동기다.

강의는 전체 규모를 약 **2.2 million images**로 소개한다. 슬라이드 7의 세부 표에서 이 수치는 GT와 hazy image를 합친 **2,200,793장**이다. 모든 image가 hazy image라는 뜻은 아니다.

| 구분 | Image 수 | 의미 |
| --- | ---: | --- |
| GT images | 130,193 | paired data의 기준이 되는 image |
| Hazy images | 2,070,600 | 합성 haze image와 Real Haze Testset을 포함한 수 |
| Total | 2,200,793 | GT와 hazy image의 합 |

GT는 Ground Truth를 뜻한다. Paired Dehazing에서는 hazy input에 대응하는 reference가 있으므로, model output을 reference와 비교하는 supervised training과 평가가 가능하다.

### Scene Type과 Haze Type

HazeSpace2M은 **네 가지 scene type**과 **세 가지 haze type**을 다룬다. 세 haze type은 Fog, Environmental Haze(EH), Cloud다.

다만 모든 scene에 세 haze type을 전부 적용한 구성은 아니다. 슬라이드 7의 Table 1은 다음과 같이 scene과 condition의 대응을 제시한다.

| Scene type | 포함하는 haze condition | Haze intensity |
| --- | --- | --- |
| Outdoor | Fog, Environmental Haze | 각 category에 10 levels |
| Street | Fog, Environmental Haze | 각 category에 10 levels |
| Farmland | Fog, Environmental Haze | 각 category에 10 levels |
| Satellite | Cloud | 10 levels |

**Scene diversity**는 배경과 object 구성의 다양성을, **haze diversity**는 열화 양상의 다양성을 의미한다. **Intensity diversity**는 같은 category에서도 열화 강도가 달라지는 설정이다.

세 축을 함께 고려하면 model이 한 scene이나 한 강도의 haze에만 맞추어지는 문제를 살펴볼 수 있다. 단, category 수가 많다는 사실만으로 실제 환경 전체를 대표한다고 단정할 수는 없다.

### Subset 구성

슬라이드 7의 Table 3은 scene별 GT와 생성된 hazy image를 구분한다. Fog와 EH가 모두 있는 scene은 같은 GT 수를 기준으로 condition별 hazy image 수가 따로 제시된다.

| Scene | GT images | Hazy images의 구성 |
| --- | ---: | --- |
| Outdoor | 35,936 | Fog 359,360 + EH 359,360 |
| Street | 39,998 | Fog 399,980 + EH 399,980 |
| Farmland | 830 | Fog 8,300 + EH 8,300 |
| Satellite | 53,429 | Cloud 534,290 |
| Real Haze Testset(RHT) | paired GT 수 미제시 | Real hazy images 1,030 |

각 합성 category의 hazy image 수에는 10 intensity levels가 반영되어 있다. 같은 GT에서 여러 열화 image가 만들어질 수 있으므로 image 수와 독립적인 원본 scene 수를 같은 것으로 해석해서는 안 된다.

RHT는 실제 haze image를 평가하기 위한 subset이다. 합성 image와 real image를 구분해 두는 것은 training condition에서의 성능과 실제 환경으로의 generalization을 분리해서 보기 위해 중요하다.

### GT Quality Assurance

Hazy input만 다양하게 만드는 것으로 paired dataset의 품질이 보장되지는 않는다. Reference 자체의 품질이 나쁘면 model이 따라야 할 target도 불명확해진다.

강의는 GT 수집 과정에서 제외 기준을 세 가지로 제시한다.

- **Resolution**: reference로 쓰기에 적합한 해상도를 고려한다.
- **Haze Presence**: GT에 이미 haze가 포함된 경우를 걸러낸다.
- **Irrelevance**: 목적에 맞지 않는 image를 제외한다.

이 기준의 역할은 haze-free reference의 적절성을 확보하는 것이다. 구체적인 resolution threshold 등은 강의 본문에 제시된 범위를 넘어 보충하지 않는다. *(슬라이드 5–7)*

## Haze-Aware Dehazing Framework

Haze-Aware Dehazing은 입력의 haze type을 판별한 다음, 그 type에 맞는 **Specialized Dehazer(SD)**를 선택한다. 모든 haze를 동일한 model로 처리하는 대신 열화 유형에 따라 restoration 경로를 달리하는 구조다.

슬라이드 8의 framework는 Training Block, Classifying Block, Dehazer Picker Block, Dehazing Block으로 구성된다.

| 단계 | 처리 | 역할 |
| --- | --- | --- |
| Training Block | HazeSpace2M으로 haze type classifier 학습 | Fog·EH·Cloud를 구분할 기준 마련 |
| Classifying Block | 입력 hazy image의 type 예측 | 입력의 열화 condition 추정 |
| Dehazer Picker Block | 예측 type에 대응하는 SD 선택 | restoration model 선택 |
| Dehazing Block | 선택된 SD에 원래 hazy image 입력 | dehazed image 생성 |

추론의 흐름은 **Hazy Image → Haze Type Classification → Specialized Dehazer Selection → Dehazed Image**다.

Classifier가 dehazed image를 직접 만드는 것은 아니다. Classifier는 어떤 dehazer를 사용할지 결정하며, 선택된 dehazer가 실제 image 복원을 수행한다.

### Specialized Model의 의미

Specialization은 haze condition별로 적합한 복원 규칙을 학습하게 하려는 접근이다. Fog, EH, Cloud의 차이를 구분하지 않고 하나의 복원 방식만 적용하면 condition별 특성을 충분히 반영하지 못할 수 있다는 문제의식에서 출발한다.

이 구조의 성능은 classifier와 dehazer 양쪽에 의존한다. 올바른 type을 골라도 dehazer의 복원 능력이 부족하면 좋은 결과를 얻기 어렵다. 반대로 강한 dehazer를 준비해도 type 선택이 틀리면 잘못된 경로를 적용하게 된다.

### Classification과 Restoration 평가

슬라이드 9는 먼저 haze type classifier의 성능을 비교하고, 별도로 dehazing 결과를 비교한다.

- **Classification evaluation**: haze type을 올바르게 구분하는지 ACC, Precision, Recall 등으로 평가한다.
- **Restoration evaluation**: 복원 image가 reference에 가까운지 PSNR, SSIM, MSE 등으로 평가한다.

Classification accuracy가 높다는 사실만으로 restoration quality가 확보되지는 않는다. Dehazing 평가까지 함께 보아야 framework의 목적을 확인할 수 있다.

강의의 Table 6에서는 Fog·EH·Cloud testset에서 SDNets를 LDNet 및 GDNet과 비교한다. 표에 제시된 평균 PSNR·SSIM·MSE는 SDNets에 유리하지만, 이 결론은 해당 testset과 비교 조건의 결과로 읽는다.

슬라이드 10은 기존 model의 pre-trained weights와 제안 framework 적용 후의 비교도 제시한다. 이 비교는 model 구조만의 효과와 동일하지 않으며, 학습과 적용 조건을 함께 고려해야 한다. *(슬라이드 8–10)*

## LoLI-Street Dataset

LoLI-Street은 도로 scene의 **Low-Light Image Enhancement**를 위한 dataset이다. 강의 본문은 **33,000 paired low-light images**와 별도의 **Real-Life Low-Light Testset(RLLT)**을 주요 구성으로 소개한다.

슬라이드 11의 dataset 비교 표에는 image quantity가 34,000으로 표시된다. 본문의 33k paired 규모와 표의 전체 표기가 다르므로, 34,000을 paired data 수로 바꾸어 읽지 않는다.

### Paired Low-Light Data

Paired data에서는 low-light image와 대응 GT를 이용해 복원 방향을 학습한다. 강의의 예시는 GT와 Light, Moderate, Dense condition을 나란히 배치해 밝기 저하 정도에 따른 차이를 보여준다.

| Condition | 강의 예시의 의미 |
| --- | --- |
| GT | 복원의 기준 image |
| Light | 상대적으로 약한 저조도 condition |
| Moderate | 중간 저조도 condition |
| Dense | 더 강한 저조도 condition |

여기서 Light·Moderate·Dense는 LoLI-Street의 low-light condition 구분이다. HazeSpace2M의 Fog·EH·Cloud라는 열화 유형 구분과는 다르다.

밝기가 낮아지면 object의 texture와 경계가 배경에 묻힐 수 있다. LLIE는 전체 intensity만 높이는 대신 구조와 detail을 함께 복원해야 한다.

### RLLT의 역할

RLLT는 실제 저조도 image에서의 평가를 위한 testset이다. Paired validation set의 결과와 real testset의 결과는 별도 조건으로 해석한다.

슬라이드 11은 train·validation·test의 average pixel intensity distribution도 보여준다. Dataset의 규모 외에 밝기 분포와 실제 image의 특성을 확인하려는 자료다.

강의의 정량 표에서 test 부분은 PSNR·SSIM 같은 reference-based metric 대신 BRISQUE와 NIQE를 제시한다. 이는 real test image의 평가에서 paired reference 기반 비교와 다른 관점이 사용됨을 보여준다. *(슬라이드 11)*

## TriFuse의 전체 구조

TriFuse는 LLIE를 위해 **Discrete Wavelet Transform(DWT)**, **Diffusion Denoising**, **Conditional Noise Module(CNM)**, **Edge Sharpening Module(ESM)**을 결합한다.

슬라이드 12의 diagram에서 low-light image는 DWT를 통해 frequency band로 분해된다. Low-frequency 성분은 denoising 경로로, high-frequency 성분은 ESM 경로로 처리한 뒤 Inverse DWT로 결합한다.

| 구성 | 주된 역할 |
| --- | --- |
| DWT | image를 low-frequency와 high-frequency band로 분해 |
| Diffusion Denoising | noise를 제거하는 역과정을 통해 복원 |
| CNM | low-light condition에 맞는 noise prediction 제공 |
| ESM | high-frequency detail과 경계를 보완 |
| Inverse DWT | 처리한 band를 image로 재구성 |

이 분리는 image 전체를 한 방식으로 처리하지 않고, 큰 밝기 구조와 세부 경계를 각각 다루려는 설계다. Low-frequency와 high-frequency는 같은 image의 표현이므로 별도 modality를 뜻하지 않는다.

### Haar Wavelet과 Frequency Decomposition

슬라이드 13은 Haar wavelet을 사용하는 2D-DWT를 다음과 같이 표현한다.

$$\{A_1^{\mathrm{low}},V_1^{\mathrm{low}},H_1^{\mathrm{low}},D_1^{\mathrm{low}}\}=\operatorname{2D-DWT}(I_{\mathrm{low}})$$

| 기호 | 의미 |
| --- | --- |
| $I_{\mathrm{low}}$ | 입력 low-light image |
| $A_1^{\mathrm{low}}$ | low-frequency approximation band |
| $V_1^{\mathrm{low}}$ | vertical high-frequency band |
| $H_1^{\mathrm{low}}$ | horizontal high-frequency band |
| $D_1^{\mathrm{low}}$ | diagonal high-frequency band |

Low-frequency band는 image의 완만한 변화와 큰 구조를 담고, high-frequency band는 방향별 급격한 변화와 detail을 담는다. TriFuse는 이 성분들을 나눈 뒤 서로 다른 module에서 처리한다.

### Forward Diffusion

Forward Diffusion은 image representation에 단계적으로 Gaussian noise를 더하는 과정이다. 강의의 transition 식은 다음과 같다.

$$q(x_t\mid x_{t-1})=\mathcal N\!\left(x_t;\sqrt{1-\beta_t}\,x_{t-1},\beta_t I\right)$$

$x_t$는 step $t$의 noisy state이고, $\beta_t$는 해당 step의 noise variance schedule 값이다. $I$는 identity matrix다.

이 과정은 저조도 image를 밝히는 단순한 intensity 조정과 다르다. Denoising model이 역과정을 학습할 수 있도록 단계적인 noisy state를 정의한다.

### Reverse Diffusion

Reverse Diffusion은 noisy state에서 noise를 제거하면서 복원된 상태로 이동하는 과정이다. 강의는 각 역방향 transition을 learned mean과 variance를 갖는 Gaussian distribution으로 표현한다.

$$p_\theta(\hat x_{t-1}\mid\hat x_t)=\mathcal N\!\left(\hat x_{t-1};\mu_\theta(\hat x_t,t),\sigma_t^2I\right)$$

$\mu_\theta$는 model이 학습하는 복원 방향을 나타내는 mean이고, $\sigma_t^2$는 역과정의 variance다. 여러 step을 거치며 restored representation을 얻는다는 것이 핵심이다.

강의 diagram의 GT/high-light branch는 forward diffusion 학습 흐름을 보여주고, low-light branch는 복원 경로를 보여준다. Diagram에 GT가 나타난다는 이유로 실제 inference마다 GT image가 필요하다고 해석하지 않는다. *(슬라이드 12–13)*

## Conditional Noise Module과 Edge Sharpening Module

### Conditional Noise Module(CNM)

CNM은 입력 condition을 반영해 noise map을 예측하는 module이다. 슬라이드 12의 구조는 Encoder, Transformer blocks, Decoder를 거쳐 predicted noise를 출력한다.

Transformer blocks는 image feature의 관계를 다루는 구성이고, predicted noise는 diffusion denoising 경로에 전달된다. 따라서 CNM의 출력은 최종 enhanced image 자체가 아니라 복원에 필요한 noise 정보다.

슬라이드 14는 이 prediction을 reverse diffusion update에 포함한다. 핵심은 현재 복원 상태와 low-light condition에 맞춘 noise prediction을 사용한다는 점이다. 해당 식의 상세 timestep·schedule 표기는 구현 명세로 확장하지 않는다.

### Edge Sharpening Module(ESM)

ESM은 high-frequency band의 경계와 세부 구조를 보완한다. Brightness가 개선되어도 object의 윤곽이 흐리면 시각적 품질과 downstream detection 모두에 제한이 생길 수 있다.

슬라이드 12의 ESM diagram에는 Depthwise Convolution, 방향별 Residual Block, Cross Attention 등이 표시된다. 서로 다른 방향의 detail을 처리하고 관계를 반영한 뒤 보정된 high-frequency band를 출력하는 흐름이다.

슬라이드 14의 residual 식은 입력 $X$에 convolution 기반 변환 결과를 더해 $Y$를 만드는 형태다. 이때 residual connection은 기존 표현에 학습된 보정량을 더하는 역할을 한다.

ESM의 전체 식도 high-frequency 성분별 처리 결과를 concatenation과 convolution으로 결합한 뒤 입력에 더하는 구조를 나타낸다. 최종적으로 복원된 low-frequency band와 보정된 high-frequency band를 Inverse DWT로 재구성한다. *(슬라이드 12–14)*

### Image Quality Metrics

PSNR, SSIM, MS-SSIM은 표에서 높은 값이 좋은 방향으로 표시된다. LPIPS, MSE, MAE는 낮은 값이 좋은 방향으로 표시된다.

Reference-based metric은 GT와 얼마나 가까운지를 측정하지만 metric마다 비교하는 성질이 다르다. 따라서 하나의 metric에서 높은 점수를 얻었다고 모든 시각적 특성이 가장 좋다고 말할 수는 없다.

RLLT 표의 BRISQUE와 NIQE는 reference image 없이 image quality를 평가하는 metric이다. 두 metric 모두 자료에서는 낮은 값이 좋은 방향으로 표시된다.

### Pre-trained와 Dataset-trained의 차이

Pre-trained weights로 새 dataset을 평가하는 것은 기존 학습 결과가 새로운 입력에 얼마나 잘 적용되는지를 보는 조건이다. LoLI-Street-trained weights를 쓰는 비교는 해당 dataset에 맞추어 학습한 뒤의 성능을 보는 조건이다.

두 결과의 차이를 architecture만의 효과로 해석하면 training data의 영향을 놓치게 된다. 슬라이드 18과 19의 visual comparison도 각각 pre-trained와 dataset-trained 조건을 구분한다.

Table 12에서 TriFuse가 모든 metric을 독점하지는 않는다. 예를 들어 Light condition의 PSNR은 LLFormer 33.40, TriFuse 32.89로 제시된다. Model 순위는 condition과 metric에 따라 달라질 수 있다.

Table 13의 trained-weights 결과에서 TriFuse는 BRISQUE 10.32, NIQE 10.61로 제시된다. 강의가 말하는 RLLT의 우수한 결과는 이 비교 조건에 한정해 이해한다.

강의의 **SOTA** 표현은 자료에서 제시한 비교 대상과 실험 결과에 대한 저자의 주장이다. 모든 dataset·metric에서의 우월성이나 현재 시점의 최신 순위를 뜻하지 않는다.

### Downstream Object Detection

슬라이드 15와 21은 enhanced image에 YOLOv10을 적용한 결과를 제시한다. Image quality와 별개로 detector가 실제 object를 더 잘 찾아내는지 확인하려는 평가다.

Table 14에는 mAP(0.5)와 mAP(0.5–0.9)가 표시된다. TriFuse의 결과는 각각 0.753과 0.692로 제시되며, 이는 표에 적힌 평가 설정에서의 detection 결과다.

해당 표의 IoU 구간은 원문 표기대로 읽어야 한다. 다른 benchmark에서 쓰는 구간으로 임의 변환하거나 동일한 평가 protocol이라고 간주하지 않는다.

Class별 결과도 균일하지 않다. TriFuse는 Person·Motorcycle·Bus·Traffic Light 등에서 좋은 결과를 보이지만, Bicycle·Car·Stop Sign에서는 다른 model이 더 높은 값을 보이는 항목이 있다.

따라서 평균 detection 성능과 class별 성능을 함께 해석한다. Enhancement가 유용하다는 결과를 모든 object class에 같은 정도로 유리하다는 주장으로 확대하지 않는다. *(슬라이드 15–21)*

## 한계와 연구 방향

Haze-Aware Dehazing의 첫 번째 한계는 **classifier dependency**다. 잘못된 haze type prediction은 적합하지 않은 dehazer 선택으로 이어지고, 최종 복원 결과를 악화시킬 수 있다.

두 번째 한계는 **synthetic-to-real gap**이다. 합성 training data가 실제 대기 상태와 scene의 복잡성을 모두 포함하지 못하면, synthetic benchmark에서의 성능이 real image에 그대로 이어지지 않을 수 있다.

Real testset은 이 차이를 관찰하기 위한 장치지만 real testset 하나에서 좋은 결과를 얻는 것만으로 모든 환경에 대한 generalization이 증명되지는 않는다.

강의는 향후 방향으로 여러 haze type을 처리하는 unified method와 computational expense가 낮은 model을 제시한다. Unified method는 type별 model 선택에 대한 의존성을 줄이려는 방향이고, 효율화는 실제 vision pipeline에서의 적용 비용과 연결된다.

이번 자료의 두 연구는 **dataset의 condition 다양성**, **condition에 맞춘 restoration**, **image quality와 downstream evaluation의 연결**을 공통적으로 강조한다. HazeSpace2M은 type별 model 선택을, TriFuse는 frequency별 처리와 conditional denoising을 중심으로 이 문제를 다룬다. *(슬라이드 22)*
