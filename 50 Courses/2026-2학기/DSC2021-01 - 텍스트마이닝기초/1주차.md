## 데이터의 형태

### 구조화 데이터와 비구조화 데이터

데이터는 구조와 형식, 매체가 제각각이다. 관계형 데이터베이스나 스프레드시트처럼 정해진 열과 자료형을 따르는 데이터는 **구조화 데이터**라고 한다. 저장 방식과 접근 방법이 데이터 모델로 정해져 있어 입력, 검색, 분석이 비교적 쉽고, 보통 SQL로 관리한다.

반대로 사진, 동영상, 웹페이지, 이메일, 블로그 글, 위키 문서, PDF처럼 하나의 고정된 틀에 맞추기 어려운 데이터는 **비구조화 데이터**다. 검색과 정리는 더 어렵지만, 그 안에는 주제와 감정, 사건, 관계처럼 중요한 정보가 들어 있다.

이름처럼 일정한 패턴은 있지만 표기 방식이 들쭉날쭉한 데이터는 **반구조화 데이터**로 볼 수 있다. 예를 들어 `Mr. Kim`과 `Kim Min-soo`가 같은 사람을 가리킬 수 있으므로, 분석 전에는 표기를 맞추는 정규화 과정이 필요하다.

> [!note] 핵심
> 텍스트가 바로 학습에 쓰이지 못한다는 뜻은 아니다. 모델에 넣기 전에 토큰, 빈도 벡터, 추출한 속성, [[Word Embedding|단어 임베딩]]처럼 일관된 표현으로 바꾸면 된다. 표 형태의 데이터는 여러 표현 방식 가운데 하나다.

### 데이터와 정보

- **데이터**는 측정하거나 수집한 원재료다. 아직 정제하거나 해석하지 않은 상태일 수 있다.
- **정보**는 데이터에서 의미 있는 내용을 추출하고 정리한 결과다.

SNS 게시물에는 작성 시각, 위치, 사용자 ID처럼 구조화된 메타데이터와 게시글 본문처럼 비구조화된 텍스트가 함께 있다. 전자는 수량 중심의 분석에, 후자는 의미와 맥락을 읽는 분석에 주로 쓰인다. 실제 분석에서는 둘을 함께 쓰는 경우가 많다.

## 텍스트와 텍스트 마이닝

### 텍스트란 무엇인가

텍스트는 사람이 쓰거나 말한 내용을 문자로 옮긴 언어 자료다. 책과 문서, 온라인 백과사전, 뉴스, 대화와 대본, 소셜 미디어 등 여러 곳에서 만들어진다. 강의 자료는 전 세계에서 초당 7PB, 하루 600PB 이상의 데이터가 만들어진다고 예시를 들며, 문제는 데이터를 모으는 일보다 그 안에서 쓸모 있는 지식을 찾는 데 있다고 설명한다.

텍스트에서는 다음과 같은 정보를 얻을 수 있다.

- 무엇을 말하는지: 주제
- 어떤 태도나 감정인지: 감성
- 누가 만들었는지: 작성자
- 언제·어디와 관련되는지: 시간과 장소
- 얼마나 반응을 얻었는지: 인기도와 사회 관계

### Text Mining이란 무엇인가

**Text Mining**, 또는 텍스트 데이터 마이닝과 텍스트 분석은 텍스트에서 질 높은 정보와 행동 가능한 지식을 찾아내는 과정이다. 대량의 글을 사람이 모두 읽는 수고를 줄이고, 판단에 쓸 근거를 만든다는 데 의미가 있다.

텍스트 마이닝은 여러 분야의 도움을 받는다. 데이터 마이닝, 정보 검색, 통계, 웹 마이닝, 전산언어학, 자연어 처리가 모두 여기에 연결된다.

### 비슷한 분야와의 차이

| 분야 | 주된 관심 | 예시 |
| --- | --- | --- |
| 데이터 마이닝 | 숫자·범주·표처럼 구조화된 데이터에서 패턴 찾기 | 우유 구매자 중 60%가 시리얼도 구매한다는 규칙 발견 |
| 텍스트 마이닝 | 비정형 텍스트에서 의미, 추세, 통찰 찾기 | 상품 리뷰에서 배터리 불만이 반복된다는 사실 발견 |
| 웹 마이닝 | 웹에서 얻는 구조화·비구조화 데이터의 패턴 찾기 | 웹 데이터 전반의 이용 패턴 분석 |
| 정보 검색 | 새 지식을 만들기보다 기존 정보 찾기 | 질의와 관련된 문서·링크 반환 |
| 전산언어학 | 언어 현상을 데이터로 분석해 자연어 처리의 근거 만들기 | `bank`가 강둑과 은행 중 무엇을 뜻하는지 문맥별 분포 분석 |
| 자연어 처리 | 언어를 이해하거나 생성하는 도구 만들기 | 번역기, 챗봇, 문법 검사기 |

통계는 텍스트 마이닝에서 찾은 패턴이 얼마나 신뢰할 만한지, 우연일 가능성은 없는지를 검증하는 기준을 제공한다. 수업의 흐름은 전산언어학이 언어 현상을 분석하고, 자연어 처리가 그 지식을 활용해 도구를 만들며, 텍스트 마이닝이 그 결과를 분석과 의사결정에 쓴다고 이해하면 된다. 실제 연구와 서비스에서는 경계가 겹친다.

> [!warning] 슬라이드 표현 읽기
> 슬라이드의 "CL과 NLP는 underlying metadata를 다룬다"는 문장은 텍스트 마이닝과 대비하려는 간략한 표현이다. 전산언어학과 자연어 처리도 텍스트 자체와 언어 구조를 직접 다룬다.

## 텍스트 분석의 기본 흐름

1. **원문 수집**: 분석할 텍스트를 모은다.
2. **전처리**: 토큰화, 불용어와 문장부호 제거, 소문자화, 표제어 추출 등을 수행한다.
3. **특징 표현**: Bag-of-Words, TF-IDF, [[Word Embedding|단어 임베딩]] 등으로 텍스트를 수치화한다.
4. **모델링**: 규칙 기반 방법, 머신러닝, 딥러닝 중 과제에 맞는 방법을 쓴다.
5. **분석과 종합**: 모델의 결과를 해석하고 필요한 통계를 확인한다.
6. **시각화와 적용**: 결과를 전달 가능한 형태로 보여 주고 실제 문제에 적용한다.

> [!note] 수업 중 보충
> 이 흐름은 강의 PDF의 개별 과제 소개보다 상세한 필기다. 실제 작업에서는 전처리, 표현, 모델링을 한 번에 끝내지 않고 결과를 보며 반복해서 조정한다.

## 대표적인 텍스트 분석 과제

### [[Sentiment Analysis]]

감성 분석은 문서, 문장, 또는 제품의 특정 속성에 대해 긍정·중립·부정의 극성을 판단하는 일이다. 1~10점 같은 척도로 표현하기도 한다. 정치인에 관한 게시글을 문서 단위로 분석하거나, 상품 후기에서 배터리와 같은 속성별 반응을 분석하는 방식이 대표적이다.

사전의 감성 단어를 활용하는 규칙 기반 방식도 있고, 예시 데이터에서 패턴을 배우는 머신러닝 방식도 있다.

### [[Term Frequency–Inverse Document Frequency|TF-IDF]]로 단어 중요도 보기

TF-IDF는 한 단어가 특정 문서에서는 자주 나타나면서 전체 문서에서는 드물게 나타날수록 높은 값을 주는 방법이다.

- **TF(Term Frequency)**: 한 문서 안에서 단어가 얼마나 자주 나오는지 나타낸다.
- **IDF(Inverse Document Frequency)**: 전체 말뭉치에서 그 단어가 얼마나 드문지 나타낸다.

$N$을 전체 문서 수, $df(t)$를 단어 $t$가 등장한 문서 수라고 하면, 한 가지 표준 정의는 다음과 같다.

$$TF(t,d)=\frac{count(t,d)}{|d|}, \qquad IDF(t)=\log\frac{N}{df(t)}, \qquad TF\text{-}IDF(t,d)=TF(t,d)\times IDF(t)$$

```text
d₁ = "The cat sat on the mat. The cat was happy."  (10단어)
d₂ = "The dog played in the park."                 (6단어)

TF("the", d₁) = 3/10 = 0.30
TF("the", d₂) = 2/6 ≈ 0.33
IDF("the") = log(2/2) = 0
```

`the`는 두 문서에 모두 들어 있으므로 문서를 구별하는 데 도움이 되지 않는다. 따라서 두 문서에서 TF-IDF가 모두 0이다. 반면 `cat`은 첫 번째 문서에만 있어 $IDF(cat)=\log(2/1)≈0.69$가 되고, 첫 번째 문서에서의 TF-IDF는 $0.2×0.69≈0.138$이다.

로그의 밑, 정규화, smoothing 방식은 도구마다 다를 수 있다. 라이브러리의 결과를 비교할 때는 어떤 정의를 썼는지 먼저 확인해야 한다.

### [[Information Extraction|정보 추출]]

정보 추출은 텍스트에서 개체와 그 속성, 개체 사이의 관계를 찾아 구조화된 정보로 바꾸는 작업이다. 비정형 또는 반구조화 문서에서 자동으로 구조를 만든다는 점이 핵심이다.

보통 어휘·구문 전처리를 한 뒤 숫자와 개체를 찾고, 지시 대상이나 대명사가 무엇을 가리키는지 해소하며, 마지막으로 개체 사이의 관계를 뽑는다. [[Named Entity Recognition|개체명 인식(NER)]]은 인명, 기관명, 지명 같은 개체를 찾는 대표 하위 과제다. 같은 표기가 어느 대상을 뜻하는지 가리는 개체명 모호성 해소와 함께 쓰인다.

- 관계 추출: `PERSON works for ORGANIZATION`, `PERSON located in LOCATION`처럼 관계를 찾는다.
- 사실 추출: `CITY has population NUMBER`, `COMPANY has turnover NUMBER`처럼 속성값을 찾는다.

### [[Text Classification|텍스트 분류]]

텍스트 분류는 미리 정한 범주 가운데 하나 이상을 문서에 부여하는 지도 학습 과제다. 호텔 후기를 읽고 주제를 `호텔`, 감성을 `긍정`으로 판단하는 것이 예다. 어휘·구문 전처리 뒤 특징을 계산하고, 규칙 기반 방법이나 지도 분류 모델을 적용한다. 실제 서비스에서는 정보 추출과 텍스트 분류를 함께 쓰는 일이 많다.

### [[Text Summarization|텍스트 요약]]

텍스트 요약은 중요한 정보와 전체 의미를 유지하면서 원문을 더 짧게 만드는 작업이다. 추출 요약은 원문 문장이나 핵심 단어를 골라 요약한다. 반대로 생성 요약은 문장을 새로 만들며, [[Transformer]]나 [[Attention]]을 쓰는 sequence-to-sequence 모델, [[Large Language Model|대규모 언어 모델]]이 대표적인 방법이다.

> [!note] 수업 중 보충
> 추출 요약과 생성 요약의 구분, Transformer 기반 요약은 강의 슬라이드의 정의를 확장한 필기다.

### [[Text Clustering|텍스트 군집화]]

텍스트 군집화는 비슷한 문서를 의미 있는 그룹으로 묶는 비지도 학습 방법이다. 정답 범주가 주어진 텍스트 분류와 달리, 문서 사이의 유사성을 바탕으로 군집을 스스로 찾는다.

- K-Means: 문서를 미리 정한 $K$개의 군집으로 나눈다. 군집 수를 정해야 한다.
- 계층적 군집화: 군집 사이의 포함 관계를 트리로 표현한다. 처음부터 $K$를 정할 필요는 없다.

### [[Topic Modeling|토픽 모델링]]

토픽 모델링은 많은 문서에서 숨어 있는 주제 구조를 자동으로 찾는 비지도 학습 방법이다. 단어가 함께 나타나는 패턴을 바탕으로 문서가 어떤 주제를 얼마나 담고 있는지 추정한다.

대표적인 Latent Dirichlet Allocation(LDA)에서는 문서 하나를 여러 토픽의 혼합으로, 토픽 하나를 여러 단어의 분포로 본다. 결과로 문서-토픽 행렬과 토픽-단어 행렬을 얻는다.

## 복습 질문

1. SNS 게시물에서 구조화된 메타데이터와 비구조화된 텍스트를 각각 하나씩 찾고, 분석할 질문을 만들어 보자.
2. "관련 문서를 찾아 달라"는 요청이 정보 검색에 가깝고, "리뷰의 공통 불만을 찾아 달라"는 요청이 텍스트 마이닝에 가까운 이유를 설명해 보자.
3. 모든 문서에 나오는 단어의 TF-IDF가 낮은 이유를 $df(t)$와 연결해 설명해 보자.
4. 정보 추출, 텍스트 분류, 텍스트 군집화, 토픽 모델링을 지도·비지도 여부와 결과물 기준으로 구분해 보자.
