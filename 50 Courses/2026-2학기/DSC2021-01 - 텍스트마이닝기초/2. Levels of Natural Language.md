> [!abstract] 핵심
> 자연어는 소리에서 문서 맥락과 사용 의도에 이르는 여러 수준으로 분석할 수 있다. Text Mining은 raw text를 token으로 나누고 형태·구문·의미 정보를 추출한 뒤 수치 표현으로 변환해 분석과 모델링에 사용한다.

## 자연어의 분석 수준

```text
Phonetics / Phonology → Morphology → Syntax → Semantics → Discourse → Pragmatics
```

| 수준 | 다루는 대상 | 예시 |
| --- | --- | --- |
| **Phonetics(음성학)** | 말소리의 물리적 실현 | `cat`의 `k` 소리 |
| **Phonology(음운론)** | 특정 언어의 소리 체계와 제약 | 영어의 `ng`는 보통 단어 처음에 오지 않지만 베트남어에서는 가능함 |
| **Morphology(형태론)** | 단어를 이루는 의미·문법 단위 | `un-believe-able` |
| **Syntax(구문론)** | 어순, 구, 절 등 단어 사이의 구조적 관계 | `The cat sat on the mat.` |
| **Semantics(의미론)** | 단어와 단어 조합의 의미 | 위 문장은 고양이가 바닥 덮개 위에 쉬고 있음을 뜻함 |
| **Discourse(담화)** | 문장을 넘어선 단락·문서의 연결과 일관성 | 여러 단락이 하나의 논지를 만드는 방식 |
| **Pragmatics(화용론)** | 맥락 속 화자의 목적과 의도 | “추워.”가 창문을 닫아 달라는 요청일 수 있음 |

Text Mining은 문자로 바뀐 자료를 다루므로 Phonetics·Phonology를 보통 직접 분석하지 않는다. sentiment처럼 여러 수준에 걸친 현상도 있어 각 수준의 경계가 항상 분명한 것은 아니다.

### 예시: 문장을 수준별로 분석하기

> The unbelievable performance left the entire audience applauding enthusiastically.

- **Morphological analysis**: `unbelievable → un + believe + able`, `applauding → applaud + ing`처럼 root와 affix를 구분한다.
- **Syntactic analysis**: 각 token의 POS를 부여하고 phrase structure나 dependency를 식별한다.
- **Semantic analysis**: performance, audience, appreciation 같은 concept와 그 관계를 파악한다.
- **Pragmatic analysis**: 강한 긍정 평가로 독자의 의견에 영향을 주려는 화자의 의도를 해석한다.

```text
Raw text → Tokenization / Lemmatization / POS tagging
         → [[Word Embedding]] / Contextual model
         → Classification·extraction 등 task → Output
```

## Token과 Morpheme

### Token과 Tokenization

**Token**은 NLP에서 보통 분석하는 가장 작은 텍스트 단위로 wordform·숫자·기호 등이 될 수 있다. Whitespace는 보통 token이 아니라 token 경계로 취급한다. **Tokenization**은 텍스트 구간을 token으로 분할하는 기본 전처리다.

- 간단한 예: `The`, `sighed`, `42`, `-`
- whitespace 분할로 처리하기 어려운 예: `i.e.`, `42.42`, URL
- 정책에 따라 결과가 달라지는 예: `isn't`, `42%`, `argument-based`

`isn't`를 하나의 token으로 볼지 `is`+`n't`로 나눌지, `42%`를 하나로 유지할지는 task와 tokenizer의 규칙에 따라 다르다.

### Morpheme

**Morpheme(형태소)**는 의미나 문법 기능을 가진 가장 작은 언어 단위다.

- `cats → cat + s`, `felt → felt`
- `speaker`의 morpheme 분해: `speak + er`
- `speaker`의 syllable 분해: `spea + ker`

Syllable은 음운적 구성 단위이고 morpheme은 의미·문법 단위이므로 분해 결과가 다를 수 있다. `cat`처럼 독립해 단어로 쓸 수 있는 것은 **free morpheme(자립형태소)**, 복수를 표시하는 `-s`처럼 혼자 쓸 수 없는 것은 **bound morpheme(의존형태소)**다.

## Morphological Normalization

**Morphological Normalization(형태 정규화)**은 관련된 어형을 하나의 표준 형태로 대표하는 과정이다. 활용형과 일부 파생형을 공통 기반으로 환원하여 다른 표면형을 같은 단어로 매칭하고 feature 차원을 줄인다.

| 방법 | 의미 | 예시 |
| --- | --- | --- |
| **Stemming** | 규칙에 따라 접사를 제거해 stem을 구함. 결과가 실제 단어일 필요는 없음 | `derive → deriv`, `am → am` |
| **Lemmatization** | 품사와 어휘 지식을 활용해 사전형인 lemma를 구함 | `derive → derive`, `am → be` |

## Syntax의 구성 단위

**Syntax**는 어순과 phrase structure의 규칙·제약을 다룬다. 자연어의 완전한 grammar를 수작업으로 모두 기술하기는 어렵다.

### Part-of-Speech

**Part-of-Speech(POS, 품사)**는 word class이며 문맥 속 구문적 기능에 따라 noun, verb, adjective, adverb, preposition, pronoun, conjunction, interjection, determiner 등으로 구분한다. **POS tagging**은 각 token에 세분화된 tag를 부여하는 전처리다.

| Token | 설명 | Tag 예시 |
| --- | --- | --- |
| `apple` | 단수 명사 | `NN` |
| `apples` | 복수 명사 | `NNS` |
| `Apple` | 고유 명사 | `NNP` |
| `sigh` | 동사 원형 | `VB` |
| `sighed` | 동사 과거형 또는 과거분사 | `VBD` 또는 `VBN` |
| `the` | 한정사 | `DT` |
| `it` | 인칭대명사 | `PRP` |

tag set은 언어와 corpus에 따라 다르며, 알 수 없는 표현은 unknown tag로 처리할 수 있다.

### Phrase와 Constituent

**Phrase(구)**는 하나의 의미 단위로 기능하는 연속된 단어열이며 내부에 더 작은 phrase를 포함할 수 있다.

```text
I [was [inside [the building]]]
```

Phrase는 문장의 constituent(구성요소)를 나타내며 두 용어는 종종 유사하게 쓰인다. **Phrase chunking(shallow parsing)**은 문장을 최상위 phrase로 나누는 분석으로, [[Named Entity Recognition|개체명 인식]] 등의 전처리에 활용된다.

### Clause와 Sentence

- **Clause(절)**: 완전한 proposition을 표현할 수 있는 가장 작은 문법 단위
  - Main clause: 독립적으로 문장이 될 수 있음. `I remained dry.`
  - Subordinate clause: main clause에 의존함. `Although it rained`, `because I was inside the building`
- **Sentence(문장)**: 하나 이상의 main clause를 포함하는 문법적으로 독립된 단위

Clause recognition은 독립 task보다 constituency parsing의 결과로 얻는 경우가 많다. **Sentence splitting(sentence segmentation)**은 문서를 개별 문장으로 나누는 기본 전처리다. 언어는 무한히 많은 문장을 만들 수 있지만, 사람은 처음 보는 문장도 이해할 수 있다.

## Semantics

### Lexical Semantics

**Lexical Semantics(어휘의미론)**은 단어와 multi-word expression의 의미, 그리고 단어 사이의 관계를 다룬다.

- **Word sense**: 같은 형태가 문맥에 따라 가지는 서로 다른 의미
  - `bank`: financial institution / river side
  - `bat`: 박쥐 / 방망이
- **Semantic role**: predicate와 argument 사이의 의미 관계
  - `The girl gave the book to her friend.`
  - `girl`: agent, `book`: theme, `friend`: recipient
- **Connotation(함축)**: truth-conditional meaning을 넘어 word choice가 전달하는 감정·문화·문체적 연상
  - `home`은 `house`보다 따뜻하고 감정적인 연상을 줄 수 있음

### Multi-Word Expression과 Word n-gram

**Multi-Word Expression(MWE)**은 하나의 어휘 단위로 기능하는 두 단어 이상의 표현이다. `driving instructor`처럼 구성적인 표현도 있고, `kith and kin`, `long time no see`처럼 관용적인 표현도 있다.

**Word n-gram**은 연속한 $n$개 단어를 하나의 특징으로 본다.

```text
The quick brown fox jumps over the lazy dog.

1-gram: The, quick, brown, ...
2-gram: The quick, quick brown, ...
3-gram: The quick brown, quick brown fox, ...
```

$m$개 token으로 된 문장에서 연속 word n-gram의 수는 $m-n+1$이다. $n$이 커질수록 어휘·구문 pattern을 더 세밀하게 담지만 가능한 조합 수와 data sparsity도 증가한다.

## 분석 과제와 텍스트 표현 수준

### 분석 수준별 대표 과제

| 수준 | 대표 과제 |
| --- | --- |
| Lexical | tokenization, sentence splitting, paragraph detection, stemming, lemmatization, POS tagging, similarity computation, spelling correction, phrase chunking |
| Syntactic | parsing, grammatical structure 식별, dependency relation, constituency structure |
| Semantic | term·named entity·relation·temporal relation extraction, topic detection, authorship attribution, [[Sentiment Analysis]], discourse parsing, spam detection, argument mining |
| Pragmatic | speaker intention, politeness·formality, implicature, deixis·reference resolution, context understanding, sarcasm, emotion·attitude, conversation flow |

Lexical·syntactic analysis가 문자열과 문법 구조에 초점을 맞춘다면, semantic·pragmatic analysis는 원문의 의미와 사용 맥락을 해석한다.

### Level of Text Representation

| 표현 수준 | 핵심 관심 | 방법 예시 |
| --- | --- | --- |
| **Lexical level** | 개별 단어와 surface form | character sequence, tokenization, stopword removal, stemming, lemmatization, word n-gram, proximity feature, POS tag |
| **Syntactic level** | 문법 구조와 단어 관계 | vector-space model([[Term Frequency–Inverse Document Frequency|TF-IDF]], [[Word Embedding]]), n-gram·neural language model, constituency·dependency parsing |
| **Semantic level** | 문장이 실제 세계에서 뜻하는 바 | template·frame, collaborative tagging·folksonomy, ontology |
| **Character level** | 개별 문자와 문자 순서 | character sequence, character-level CRF·RNN·LSTM; 형태가 복잡한 언어와 unseen word 처리 |

> [!note] 해석
> 이 분류는 개념적 구분이다. embedding은 단어를 vector로 바꾸는 표현 방법이지만 학습 방식에 따라 syntactic·semantic information을 함께 담을 수 있다.

## Text Mining and Analysis Pipeline

```text
Text Input → Text Preprocessing → Text Transformation
           → Semantic Analysis → Interpretation / Evaluation
```

1. **Text Input**: document, report, website, social media, email 등에서 raw text를 수집한다.
2. **Text Preprocessing**: 광고·markup 제거, 형식 정규화, table·figure·formula 처리, tokenization, sentence splitting, stemming·lemmatization, stopword removal, POS tagging, [[Word Sense Disambiguation]], syntactic structure 분석을 수행한다.
3. **Text Transformation**: Bag-of-Words, [[Term Frequency–Inverse Document Frequency|TF-IDF]], [[Word Embedding]] 등으로 텍스트를 수치 feature로 바꾼다.
4. **Semantic Analysis**: word sense, semantic structure, topic, semantic similarity 등을 분석해 의미와 맥락을 파악한다.
5. **Interpretation / Evaluation**: 결과를 해석·시각화하고 model performance와 business value를 평가해 actionable insight를 만든다.

각 단계는 이전 단계의 결과에 의존하며, 평가 결과에 따라 전처리나 표현 방식으로 돌아가 반복할 수 있다.

### 주요 전처리 이슈

- **Tokenization**: apostrophe, hyphen, `C++`, `A/C`, emoticon, 여러 whitespace 등의 처리 규칙이 필요하다.
- **Stemming·Lemmatization**: 관련 단어를 통합해 매칭 효과를 높이고 term vector의 크기를 줄일 수 있다.
- **POS tagging**
  - Rule-based: grammar rule에 의존한다.
  - Statistical: word order probability와 수동 tagged corpus로 학습한다.
- **Word Sense Disambiguation(WSD)**: 다의어가 문장에서 어느 의미로 쓰였는지 판별한다. `The king saw the rabbit with his glasses.`처럼 수식 관계가 모호한 문장은 여러 해석을 가진다.
- **Full parsing vs. partial parsing**
  - Full parsing은 문장 전체의 parse tree를 만든다.
  - Chunking·partial parsing은 noun phrase, verb group 같은 일부 구조만 찾는다.
  - 비문, novel word, 잘못된 tokenization·sentence split·POS tag로 full parsing이 실패하기 쉬워 실용 상황에서는 partial parsing이 자주 사용된다.
- **Stopword removal**: `the`, `of`, `and`, `to`, `is`처럼 빈번하지만 과제에 덜 유용한 단어를 제거한다. dataset을 줄이고 noise를 완화하며 필요하면 domain-specific list를 추가한다. 다만 sentiment, negation, authorship task에서는 기능어도 중요할 수 있어 무조건 제거하지 않는다.
