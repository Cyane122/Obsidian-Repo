- 무엇을 해결하려고 시작했는가

- 실험이나 사용자 정정으로 무엇이 바뀌었는가
- 어디까지 구현됐고 무엇은 아이디어 단계인가

# AI·데이터·지식 프로젝트

## 서사 시스템 계열

### [[GraphRAG]]

그래프 기반 세계 상태, 장기 기억, 관계 변화와 여러 후처리 시스템을 결합한 롤플레이 시뮬레이션 엔진이다. Kuzu 그래프 런타임에서 시작해 Markdown Wiki를 저장소로 사용하는 WikiRAG 실행 방식까지 확장됐다. LLM이 곧바로 세계를 고치는 것이 아니라 제안을 만들고, 결정론적 검증·적용기가 커밋하는 구조가 중심이다.

### [[Narragraph]]

GraphRAG의 자유 대화형 구조와 다른 방향을 시험한 저작형 인터랙티브 픽션 엔진이다. 작가가 만든 이동·조건·상태 전이를 결정론적으로 실행하고, LLM은 허용된 서사 구간만 채운다. 단일 `GameState`, 상태 권한의 단계 구분, 시간 비용 기반 진행이 핵심 불변식이다.

### [[서사 생성 모델 연구 프로토타입]]

Story State만 유지하는 생성에서 더 나아가 독자가 무엇을 알고·믿고·느끼는지를 Reader State로 표현하고, Narrative Intent가 다음 장면의 독자 상태 변화를 목표로 삼게 하는 연구 구상이다. 새 모델을 처음부터 학습하기보다 기존 decoder-only 모델의 구조화 프롬프트 기준선을 먼저 만들고 평가하는 순서로 설계됐다.

이 세 프로젝트는 같은 문제를 서로 다른 층에서 다룬다.

```text
GraphRAG
자유 대화형 세계 시뮬레이션과 장기 상태
        │
        ├─ 자유도를 줄이고 저작권한을 강화 → Narragraph
        │   결정론적 인터랙티브 픽션 엔진
        │
        └─ 생성 품질을 연구 질문으로 추상화 → 서사 생성 모델 연구 프로토타입
            Story State + Reader State + Narrative Intent
```

## 지식과 정보 운영 계열

### [[AI·NLP 학술 지식 Wiki]]

논문을 한 편씩 요약하는 데 그치지 않고 paper·concept·map·comparison·synthesis 노트로 분해해 연결하는 Obsidian 저장소다. 폴더·frontmatter·태그·링크 규칙과 감사 스크립트를 별도 스킬로 만들어, 세션이 바뀌어도 같은 방식으로 지식을 편입할 수 있게 했다.

### [[데이터·AI 데일리·주간 브리핑]]

새 채용·논문·기술 소식을 매일 발견하고, 한 주의 데일리 기록에서 중요한 흐름만 다시 압축한다. 공식 원문을 사실의 기준으로 두고 커뮤니티는 탐색 신호로만 사용한다. 당일 상태와 보고서를 함께 확인해 실패와 중복 실행을 구분한다.

두 프로젝트는 모두 ‘수집보다 선별과 축적’을 중시한다. 브리핑이 시간에 민감한 새 정보를 발견하는 입구라면, 학술 Wiki는 오래 남길 개념과 논문을 구조화하는 저장소다. 아직 두 시스템 사이에 자동 승격 경로가 있다는 기록은 없지만, 브리핑에서 고른 논문을 Wiki 편입 후보로 넘기는 흐름은 자연스러운 접점이다.

## 모델링과 평가 계열

### [[Two-stage 추천 시스템]]

MovieLens-1M을 사용자별 시간순으로 나눠 ALS·인기 후보를 만들고 LightGBM으로 재정렬했다. 후보 Recall과 상위 nDCG를 분리해 진단했으며, 후보 수를 무작정 늘리면 Recall 상한은 좋아져도 실제 nDCG가 낮아질 수 있음을 확인했다.

### [[CH2026 센서 데이터 예측]]

생활 센서의 여러 타깃을 대상으로 시간·수면·의미 특징, 시퀀스 모델, 트리 스택, 피험자 홀드아웃과 OOF 블렌드를 실험했다. 로컬 OOF 최고 모델과 Public LB 최고 제출을 분리해 기록하며, 사용자가 정정한 최종 Public logloss `0.5974867204`를 보존했다.

두 프로젝트 모두 모델 이름보다 평가 설계를 먼저 본다는 공통점이 있다. 추천 시스템에서는 per-user와 global split의 차이를, 센서 프로젝트에서는 시간·피험자 일반화와 Public LB의 차이를 문제 정의의 일부로 다뤘다.

## 개인 워크플로 자동화

### [[개인 지출 기록 자동화]]

금융 앱에 직접 로그인하지 않고 Android 알림만 Tasker로 받아 구조화된 Gmail 메시지로 만든다. 확실한 파싱은 결정론적 코드가 맡고, 애매한 중복·취소 연결은 후속 AI가 검토하는 구조다. 첫 마일스톤은 52개 테스트와 함께 완료됐지만 Google Sheets 장부 반영 단계는 아직 구현이 확인되지 않는다.

# 취미·게임·개인 서비스

## [[스텔라이브 음악·채널 서비스]]

스텔라이브의 커버·오리지널 곡과 참여 조합을 표 형태로 탐색하고 등록 영상의 조회수를 갱신하는 팬 데이터 서비스다. 누락곡 하나가 통계를 뒤집은 경험 때문에 원본 목록과 분석 규칙을 분리했다. Google 로그인, 개인 구독, YouTube 새 영상과 치지직 라이브 알림은 후속 확장안으로 설계됐다.

## [[로스트아크 기상술사 딜 최적화기]]

캐릭터 API와 게임 효과 데이터를 이용해 약 88만 개의 세팅 조합을 비교하는 계산 도구다. 실측 스킬 지분을 기준 세팅에서 역산한 뒤 후보 효과를 적용하고, CPU와 WebGPU가 같은 계산 의미를 갖게 했다. 기상술사에서 출발해 환수사와 배틀마스터 등으로 넓어졌으며, 사용자의 게임 지식 정정이 계산 결과를 여러 차례 바꿨다.

## [[아크 그리드 코어 기록장]]

로스트아크 캐릭터 6명의 주간 레이드 코어와 천장 결과를 별도로 기록하는 개인 사이트다. 한국 시간 수요일 오전 6시를 주차 경계로 사용하고 브라우저에 즉시 저장한다. 서버가 없어 간단하지만 기기 간 동기화와 백업은 제공하지 않는다.

게임 프로젝트 둘은 같은 도메인을 공유하지만 목적은 다르다. 코어 기록장은 실제 획득 결과를 누적하는 관찰 도구이고, 딜 최적화기는 현재 보유 자원과 효과 규칙으로 더 나은 조합을 찾는 의사결정 도구다. 기록장의 장기 분포가 최적화기의 기대 가치 계산으로 연결됐다는 근거는 아직 없다.

# 프로젝트 전반에서 반복된 설계 성향

## LLM의 권한을 제한한다

GraphRAG와 Narragraph에서는 LLM이 상태를 직접 쓰지 않고 제안·서술을 맡는다. 지출 자동화에서도 확실한 형식화는 파서가 담당하고 AI는 애매한 의미 판단을 맡는다. 생성 능력을 쓰되, 복구하기 어려운 상태 변경은 결정론적 경계 안에 둔다.

## 원본과 해석을 분리한다

학술 Wiki는 출처와 종합 노트를 연결하고, 스텔라이브 서비스는 곡 원장을 보존한 채 통계별 제외 규칙을 둔다. 지출 자동화도 파싱 실패 때 원문을 지우지 않는다. 잘못 정리된 깨끗한 데이터보다 나중에 다시 판단할 수 있는 원본을 선호한다.

## 평균 하나보다 실패 구조를 본다

추천에서는 후보 Recall과 nDCG, 센서 예측에서는 OOF와 Public LB, 딜 계산기에서는 테스트 통과와 실제 게임 공식의 정확성을 구분했다. 지표 하나가 좋아도 다른 검증축이 나빠질 수 있다는 전제가 반복된다.

## 작은 운영 단위로 먼저 완성한다

지출 자동화는 서버 없이 Tasker→Gmail부터, 아크 그리드 기록장은 로컬 저장부터, 서사 연구는 새 모델 학습보다 구조화 프롬프트 기준선부터 시작했다. 확장 가능성은 열어 두되 첫 검증 전에 운영 복잡도를 키우지 않는 편이다.

# 다시 확인할 우선순위

1. **현재도 활발한 프로젝트**: GraphRAG의 provider 중복과 경계 테스트, 학술 Wiki의 지속 편입 흐름을 먼저 확인한다.
2. **구현과 설계가 섞인 프로젝트**: 스텔라이브 알림 확장과 지출의 Sheets 단계를 실제 코드 기준으로 분리한다.
3. **외부 데이터가 변하는 프로젝트**: 로스트아크 계산기의 최신 패치·API·수기 데이터 버전을 검증한다.
4. **최종 상태가 불명확한 프로젝트**: CH2026의 Private 결과, 아크 그리드 사이트와 로컬 데이터의 생존 여부를 확인한다.
5. **연구 단계 프로젝트**: 서사 생성 모델은 첫 기준선 실험과 평가셋을 만들기 전까지 아이디어와 결과를 구분해 기록한다.

# 포함·제외 기준

- 독립적인 목표, 반복 작업 또는 유지할 산출물이 있어야 포함한다.
- 게임·팬 활동처럼 AI와 무관해도 개인 도구나 데이터 자산으로 지속성이 있으면 포함한다.
- 외부 프로젝트의 설치와 연동만 확인된 경우는 보류한다.
- 게임 공략, 시험장 탐색, 교재 추천처럼 독립 산출물이 없는 대화는 프로젝트로 만들지 않는다.
- 새 세션에서 목표·산출물·상태 변화가 확인되면 이 지도와 해당 프로젝트 노트를 함께 갱신한다.
