## Structured vs. Unstructured
- 데이터는 다양한 구조, 형태, 매체로 존재한다.
- 어찌됐든 학습하려면 구조화된 데이터여야 한다.
- 보통: Unstructured인 textual 데이터에서 ID, AGE, Birthday 등의 구조화된 데이터를 추출(extract)하여 학습에 사용한다.
- 추출된 데이터는 통계적 분석 또는 학습에 사용한다.
- 텍스트 데이터를 표(tabular) 데이터로 만들어야 학습에 사용할 수 있다. -> 표 = 구조화!
- 표 형태의 데이터에서 추출한 데이터는 구조화된 데이터다.
- 이름 = semi-structured data (e.g. Mr. Kim과 Kim Min-soo는 같은 사람이지만 텍스트 형태가 다르므로 정규화가 필요함)

> [!note] 핵심 판단
> 텍스트가 곧바로 "학습 불가"라는 뜻은 아니다. 다만 모델에 넣기 위해서는 token, 빈도 벡터, embedding, 추출한 속성처럼 **일관된 표현**으로 변환해야 한다. 표 형태의 구조화 데이터는 그중 하나의 표현이다.

- 데이터와 정보의 차이:
	- Data: 측정되거나 수집된 것. 아직 정제되거나 정리되지 않음
	- Information: 데이터에서 추출한 무언가 의미있는 것

- Structured data: refers to data with a high level of organization, such as in relational databases and spreadsheets.
	- depends on a data model -- a model of the data
	- types and how they will be stored, processed and accessed
	- easily entered, stored, queried and analyzed.
	- Structured Query Language(SQL) is used for management of structured data.
- Unstructured data: means all things that cannot be classified(라벨링 불가) and fit into one simple model. -- hard to search, organize / various formats.
	- photos and graphic images
	- videos
	- streaming instrument data
	- webpages, emails, blog entries, wikis
	- PDF files, pptx, documents

- 가장 많은 데이터가 있는 SNS 등지에는
	- 구조화된 데이터인 메타데이터 (type of post, day, location, user id, age, etc)
	- 비구조화된 데이터 (text -- topic, entities, content, insights, etc)
	- 가 동시에 존재한다.
	- 구조화된 데이터는 보통 quantitative analysis에 사용 / unstructured는 semantic or qualitative analysis에 사용

## What is Text?
- Text refers to any written or transcribed language produced by humans, which can be processed and analyzed to extract information and knowledge.
- 출처도 다양함(책/문서, 온라인 백과사전, 뉴스/기사, 대화/대본, 소셜 미디어)
- 쌓이는 양도 괴랄함(초당 7PB / 하루에 600PB 이상)
- 데이터 수집뿐 아니라 유용한 정보를 추출하는 것이 Text Mining이다.

- 텍스트 데이터의 양:
	- Total volume: 150~300ZB
	- Daily: 10~30PB
- 무엇을 얻을 수 있을까?
	- 주제, 시간, 장소, 감성, 저자, 유명함, 사회 관계망 등

## What is Text Mining?
- Text Mining(=Text Data Mining, Text Analytics): process of deriving high quality information or actionalble knowledges from texts
- Helps us: Minimizes human efforts / Supplies Knowledge for Optimal decision making
- Core Components:
	- Data Mining: deals with both text and non-text data
		- extracts patterns from structured data (numbers, categories, tables)
	- Information Retrieval
	- Statistics
	- Web Mining
	- Computational Linguistics
	- Natural Language Processing

### 인접 분야와의 구분

| 분야 | 주된 입력·목적 | 산출 예시 |
| --- | --- | --- |
| Data Mining | 수치·범주·표 등 구조화 데이터의 패턴 탐색 | "우유 구매자 중 60%가 시리얼도 구매" |
| Text Mining | 대규모 비정형 텍스트에서 의미·추세·통찰 추출 | 리뷰에서 배터리 불만 추세 발견 |
| Web Mining | 웹에서 얻는 구조화·비구조화 데이터의 패턴 탐색 | 웹 데이터 기반 패턴 분석 |
| Information Retrieval | 새 지식을 만들기보다 이미 있는 관련 정보를 찾음 | 질의에 맞는 문서·링크 반환 |
| Computational Linguistics (CL) | 언어 현상을 데이터로 분석해 NLP의 근거를 만듦 | 문맥에 따른 `bank`의 의미 분포 분석 |
| Natural Language Processing (NLP) | CL의 지식을 활용해 언어 이해·생성 도구를 만듦 | 번역, 챗봇, 문법 검사 |

- Statistics는 Text Mining 결과의 신뢰성·유의성·불확실성을 검증하는 수학적 토대를 제공한다.
- 강의의 큰 관계는 `CL의 언어 분석 → NLP 도구 → Text Mining의 통찰·의사결정`으로 이해하면 된다. 실제 연구와 서비스에서는 이 경계들이 겹친다.

## Text Mining vs. CL and NLP

- Text Mining: 텍스트의 관측 가능한 특징과 그로부터 얻는 패턴·통찰에 집중
	- Frequency count of words
	- Sentence length
	- Word spectrum
	- Presence/absence of key words

- CL: 대규모 말뭉치에서 언어 현상을 통계적으로 분석한다.
- NLP: CL을 포함한 언어 지식을 이용해 언어를 이해·생성하는 실용 도구를 만든다.

> [!warning] 슬라이드 해석
> 슬라이드의 "CL and NLP가 underlying metadata를 다룬다"는 표현은 두 분야의 전체 정의가 아니라 Text Mining과의 대비를 위한 단순화로 읽는다. CL/NLP도 텍스트 자체와 언어 구조를 직접 다룬다.

### Sentiment Analysis
- Goal: to determine the polarity of a given text at the document, sentence, or feature/aspect level
- Polarity values: Positive, neutral, negative or Likert scale (1 to 10)
- Application examples
	- Document level: Analysis of tweets about politicians
	- Feature/aspect level: Analysis of product reviews
- Approaches
	- Rule-based -> Lexicons
	- Machine learning -> learn patterns

### Analyzing word and document frequency (TF-IDF)
- Text Frequency와 Inverse Document Frequency의 곱.
- Text Frequency (TF): 특정 문서 내에서 특정 단어가 얼마나 중요한지(얼마나 자주 등장하는지)를 나타내는 지표.
- Inverse Document Frequency (IDF): 전체 corpus 내에서 단어가 얼마나 흔치 않거나 드물게 등장하는지를 나타내는 지표.

표준적인 한 가지 정의는 다음과 같다. $N$은 전체 문서 수, $df(t)$는 단어 $t$가 등장한 문서 수다.

$$TF(t,d)=\frac{count(t,d)}{|d|}, \qquad IDF(t)=\log\frac{N}{df(t)}, \qquad TF\text{-}IDF(t,d)=TF(t,d)\times IDF(t)$$

```
corpus=[
	"The cat sat on the mat. The cat was happy.",
	"The dog played in the park."
]

TF("the", d1) = count(d1, "the")/len(d1) = 3/10 = 0.3
TF("the", d2) = count(d2, "the")/len(d2) = 2/6 ≈ 0.33
IDF("the") = log(전체 문서 수 / "the"가 등장한 문서 수) = log(2/2) = 0

TF-IDF("cat", d1) = TF("cat", d1) x IDF("cat", d1)
	=> TF = 2/10
	=> IDF = log(2/1) = ~0.69
	= TF-IDF = 0.138
```

- 따라서 `the`의 TF-IDF는 `d1`, `d2` 모두 0이다. 모든 문서에 등장해 문서 구별력이 없기 때문이다.
- 로그의 밑, 정규화, smoothing 방식은 구현마다 다를 수 있으므로 라이브러리 결과를 비교할 때는 정의를 먼저 확인한다.

### Information Extraction
- Identification of entites, their attributes, and their relations in text
- Task of automatically extracting structured information from unstructured or semi-structured documents
#### Possible text analysis steps
1. Lexical and syntactic preprocessing
2. Named and numerical entity recogition
3. Reference resolution
4. Entity relation extraction

- [[Named Entity Recognition|NER]]는 개체명 인식의 대표 하위 과제다. 동일한 표기가 어느 대상을 뜻하는지 가리는 disambiguation, 대명사 등이 무엇을 가리키는지 푸는 reference resolution과 함께 쓰인다.

#### Subtasks
1. Named Entity Recognition and Disambiguation
	- `The parliament in Berlin has decided...`
	- Which parliament? Which Berlin?
2. Relationship Extraction
	- PERSON works for ORGANIZATION
	- PERSON located in LOCATION
3. Fact Extraction
	- CITY has population NUMBER
	- COMPANY has turnover NUMBER (Unit)

### Text Classification
- Assignment of a text to one class from a given set of classes.
```python
"""
This was truly a lovely hotel to stay in.
The staff were all freiendly and very helpful.
"""

=> Topic: "Hotel", Sentiment: "Positive"
```

#### Possible text analysis steps
1. Lexical and syntactic preprocessing
2. Feature computation(rule-based) and supervised classification

- 핵심은 미리 정한 class 중 하나 이상을 예측하는 **supervised** task라는 점이다. 정보 추출과 함께 적용되는 경우가 많다.

### Text Summarization
- Automatically creating a shorter version of a text document that retains the most important information and overall meaning
- Extractive: 단어 빈도, TextRank, LexRank 등에 따라 요약
- Abstractive: [[Transformer]], Seq2Seq [[Attention]] Model, Pretrained LLM을 활용해 요약

> [!note] 수업 중 보충
> Extractive·abstractive 구분과 Transformer 기반 요약은 슬라이드의 정의를 확장한 필기다. 개념 연결은 [[Transformer]], [[Attention]], [[Large Language Model]]에서 이어서 본다.

### Text Clustering
- Automatically groups a collection of text documents into meaningful categories, called clusters.

#### Algorithms
1. K-Means Clustering: 문서들을 K개의 클러스터로 나눈다. 원형의 클러스터들이 생긴다.
2. Hierarchical Clustering: 계층 트리로 클러스터링한다. K를 정할 필요가 없다.

- 정답 class가 주어진 Text Classification과 달리, Text Clustering은 문서 간 유사성으로 군집을 발견하는 **unsupervised** 방법이다.

### Topic Modeling
- Automatically discovers the hidden thematic structure in a large collection of documents. It's a form of text mining for finding and tracing patterns of words.

#### Latent Dirichlet Allocation (LDA)
- 각각의 토픽을 문서에 할당한다? 는 뜻인 것 같은데
- 한 문서가 여러 토픽을 가질 수 있다
- For each document: Extract a Mix of Topics
- For each topic: Extract a Mic of Words
- Results: Document-Topic matrix, Topic-Word matrix

- 문서 하나는 여러 topic의 혼합으로, topic 하나는 여러 단어의 분포로 표현된다는 관점이 핵심이다.
