# Academic wiki workflow

이 문서는 자료를 학술 지식층에 편입하거나 여러 문서를 함께 다룰 때 읽는다. 폴더와 frontmatter의 기준은 `90 Meta/Vault Schema.md`에 있고, 여기서는 어떤 순서로 판단하고 쓰는지만 다룬다.

## 1. 범위와 근거 수준 정하기

요청을 `ingest`, `update`, `query`, `compare`, `synthesize`, `review`, `audit` 중 하나 이상으로 나눈다. 질문의 범위는 학술 지식, 특정 논문, 연구 흐름, 수업, 프로젝트, Wiki 관리 가운데 먼저 고른다. 이 스킬은 `10`~`40`의 학술 영역만 편집한다.

[retrieval-policy.md](retrieval-policy.md)의 사다리를 따라 identity, structured metadata, lexical content, graph context, semantic similarity 순서로 후보를 좁힌다. `summary`와 semantic search 결과는 문서를 고르는 단서일 뿐 근거가 아니다. 최종 판단은 필요한 본문이나 원문에서 확인한다.

별도 registry 파일을 손으로 관리하지 않는다. 실제 Markdown의 path, frontmatter, links에서 검색 결과와 Bases view를 파생시킨다.

## 2. 자료 수집과 병합

자료 하나에서 여러 위키 동작이 나올 수 있다.

```text
논문 PDF
├─ paper 노트 생성 또는 갱신
├─ 재사용 가능한 핵심 개념 문서 갱신
├─ comparison·synthesis에 필요한 근거 추가
└─ 관련 topic map의 연구 흐름 갱신
```

쓰기 전 다음 동작을 내부적으로 결정한다.

| 대상 | 동작 | 근거 |
|---|---|---|
| 기존 canonical 문서 | update | 같은 정의·논문·질문을 다룬다 |
| 새 canonical 문서 | create | 독립적으로 재사용할 가치가 있고 기존 대상이 없다 |
| 관련 지도 | link/update | 새 자료가 흐름·분류·탐색 경로를 바꾼다 |
| 약한 후보 | mention only | 별도 문서로 유지할 가치가 아직 없다 |
| 이미 충분한 문서 | unchanged | 새 자료가 정의·근거·맥락을 실질적으로 바꾸지 않는다 |

자료 하나를 파일 하나로 대응시키지 않는다. 한 논문에서 paper 노트를 만들면서 기존 concept를 보강할 수도 있고, 반대로 서지 정보만 확인한 자료는 paper의 상태만 갱신하고 새 concept를 만들지 않을 수도 있다.

### 병합 규칙

- 기존 문서의 더 일반적이고 정확한 정의를 기준으로 새 근거를 통합한다.
- 새 자료가 기존 주장과 충돌하면 하나를 지우지 말고 조건·출처·평가 설정의 차이를 설명한다.
- 사용자가 작성한 해석은 출처 요약과 섞어 재작성하지 않는다.
- 동일한 문장을 누적하지 말고 해당 섹션을 응집된 설명으로 다듬는다.
- 문서 전체를 교체하지 말고 필요한 frontmatter와 섹션만 수정한다.

## 3. 링크와 출처

링크를 만들기 전 [linking-policy.md](linking-policy.md)에 따라 파일명, `title`, `aliases`, 본문 맥락을 확인한다. 이미 canonical 문서가 있거나, 현재 내용을 이해하는 데 독립된 정의가 필요하거나, 출처 관계 자체가 지식일 때만 연결한다. 같은 basename이 여러 개면 가장 짧은 구분 경로를 사용한다. 코드 블록, 수식 내부, YAML 문자열의 일반 텍스트에는 링크를 삽입하지 않는다.

- paper는 `url`과 `pdf`로 원문을 추적한다.
- concept는 `등장/대표 논문`과 필요한 본문 링크로 근거를 연결한다.
- comparison과 synthesis는 YAML `sources`와 본문의 개별 `[[paper]]` 링크를 함께 사용한다.
- PDF의 특정 근거는 `[[...pdf#page=N]]`으로 연결한다.
- 원문에서 직접 확인하지 못한 해설은 [provenance-policy.md](provenance-policy.md)에 따라 callout 또는 명시적인 해석 문장으로 구분한다.

## 4. 지도·비교·종합

### Map

map은 문서 목록이 아니라 탐색 경로다. 시간순 나열만 하지 말고 각 연구가 이전 한계를 어떻게 바꾸었는지 쓴다. 새 자료가 기존 흐름의 위치를 바꾸거나 중요한 분기를 만들 때 갱신한다.

### Comparison

비교 대상 모두에 적용 가능한 축만 사용한다. 수치 비교에서는 데이터셋, split, metric, 모델 규모, 학습 조건이 실제로 비교 가능한지 먼저 확인한다. 비교 불가능한 결과를 한 순위로 합치지 않는다.

### Synthesis

다음 조건에서 synthesis를 만든다.

- 둘 이상의 출처를 함께 읽어야 답할 수 있는 재사용 가능한 질문이다.
- 개별 paper나 concept만으로는 합의·긴장·연구 공백을 설명하기 어렵다.
- 관련 문서가 대략 5개 이상 쌓여 상위 관점이 필요하다.

최소한 범위와 핵심 결론, 합의, 조건별 차이, 약하거나 충돌하는 근거, 미해결 질문과 다음 읽기 경로를 포함한다.

## 5. 위키 질의

1. `90 Meta/Vault Schema.md`에서 질문 유형에 맞는 범위를 고른다.
2. [retrieval-policy.md](retrieval-policy.md)의 사다리로 후보를 좁히고 필요한 섹션만 읽는다.
3. 답변의 핵심 주장에 `[[wikilink]]`로 위키 근거를 표시한다.
4. 문서 간 모순, 근거 부족, `maturity: stub`을 숨기지 않는다.
5. 사용자가 저장을 요청했거나 결과가 반복해서 참조할 독립 지식일 때만 comparison·synthesis로 저장한다.

## 6. 감사와 유지관리

감사는 기본적으로 report-only다. [audit-policy.md](audit-policy.md)의 규칙 단위 결과와 `scripts/audit-vault.ps1`을 함께 사용한다. 오류, 경고, 정보성 후보를 구분하고 자동 수정 가능 여부를 별도로 표시한다.

- 중복 basename과 alias 충돌
- 누락·오류 frontmatter와 폴더·`type` 불일치
- 미등록 태그와 태그 수 초과
- 존재하지 않는 PDF와 잘못된 읽기 상태
- 미해결 위키링크와 고아 문서 후보
- 여러 문서가 쌓였지만 map·synthesis가 없는 주제
- 출처보다 강한 주장, 서로 충돌하는 주장, 오래된 평가

수정 순서는 `깨진 구조 → 잘못된 메타데이터 → 링크 → 중복 → 종합 부족`으로 잡는다. 대량 수정 전에는 대상과 예상 변경 수를 보고하고 Dry Run이 있는 스크립트를 우선 사용한다. legacy 위치나 v2 도입 필드의 누락은 보고만 하며, 사용자의 승인 없이 이동하거나 일괄 채우지 않는다.
