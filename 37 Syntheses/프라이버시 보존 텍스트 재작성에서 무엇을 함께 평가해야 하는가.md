# 핵심 결론

프라이버시 보존 재작성은 단일 “익명화 점수”로 평가할 수 없다. 공격자가 민감 속성이나 신원을 추론하지 못하는지, 원문의 의미와 downstream utility가 남는지, 결과가 자연스러운지를 최소 세 축으로 분리해야 한다. 또한 [[Anonymity at Risk - Assessing Re-Identification Capabilities of Large Language Models in Court Decisions]]가 보여 주듯 재식별 위험은 모델 규모뿐 아니라 공개 보조정보와 입력 길이, 데이터 도메인에 크게 좌우된다.

# 합의되는 내용

- 단순 식별자 삭제는 문맥적 단서와 문체 기반 추론을 막지 못한다.
- 프라이버시를 강하게 만들수록 의미 보존과 자연스러움이 손상될 수 있으므로 Pareto trade-off로 보고해야 한다.
- 자동 지표 하나만으로는 부족하다. [[NAP² - A Benchmark for Naturalness and Privacy-Preserving Text Rewriting by Learning from Human]]와 [[Zero-Shot Privacy-Aware Text Rewriting via Iterative Tree Search]]는 privacy, utility, naturalness를 함께 측정하고 인간 평가를 보조적으로 사용한다.

# 조건에 따른 차이

[[Zero-Shot Privacy-Aware Text Rewriting via Iterative Tree Search]]는 reward-guided 반복 탐색으로 삭제·추상화를 조합한다. 반면 [[IncogniText - Privacy-enhancing Conditional Text Anonymization via LLM-based Private Attribute Randomization]]는 공격자가 잘못된 민감 속성 값을 예측하도록 조건부 무작위화를 사용하고 on-device 증류까지 다룬다. 전자는 검색 비용과 reward 품질, 후자는 목표 속성 정의와 오도 전략의 윤리·안전성이 핵심 조건이다.

# 충돌과 근거의 한계

재식별 성공률과 속성 추론 정확도는 같은 위험이 아니며, 데이터셋과 공격자 지식이 다르면 직접 비교할 수 없다. [[Perplexity]]나 의미 유사도도 자연스러움과 의미 보존의 완전한 대리 지표가 아니다. 경험적 공격 저항은 [[Differential Privacy]] 같은 형식적 보장을 의미하지 않는다.

# 미해결 질문

- 공개 웹 검색과 외부 데이터 결합을 허용한 강한 공격자에서도 결과가 유지되는가?
- 여러 민감 속성을 동시에 보호할 때 교차 속성 단서가 다시 나타나는가?
- 프라이버시를 위해 의도적으로 잘못된 속성을 만들 때 원문의 사실성과 책임 소재를 어떻게 관리할 것인가?
