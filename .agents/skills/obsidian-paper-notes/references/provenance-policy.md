# Provenance policy

문서에서 무엇이 원문에 있고 무엇이 해석인지 구분한다. 수치형 confidence나 typed relationship은 현재 schema에 넣지 않는다. 유지 비용보다 실제 판단에 도움이 되는 구분만 사용한다.

## 근거의 종류

| 종류 | 기록 방식 |
|---|---|
| 원문 사실·수치 | paper의 `url`, `pdf`, 필요한 페이지 링크로 추적한다 |
| 저자의 주장 | 저자가 제시한 결론임을 문장에 드러낸다 |
| 여러 출처의 합의 | synthesis에서 출처를 나란히 연결한다 |
| 출처 간 충돌 | 데이터, 조건, 평가 설정의 차이와 함께 남긴다 |
| 작성자의 해석 | 본문에서 해석임을 밝히거나 `> [!note] 해설`로 분리한다 |
| 흔한 오해·주의 | `> [!warning] 주의`로 분리한다 |
| 확인하지 못한 내용 | `확인되지 않음`, `원문 확인 필요`처럼 상태를 적는다 |

paper는 한 논문을 추적하므로 `url`과 `pdf`가 근거의 중심이다. concept는 `등장/대표 논문`과 본문 링크를 사용한다. comparison과 synthesis는 YAML `sources`에 실제로 판단에 사용한 문서만 넣고, 핵심 주장 가까이에 개별 링크를 둔다.

## 주장 강도

- 실험 결과보다 넓은 일반화를 만들지 않는다.
- 경험적 공격 저항을 형식적 프라이버시 보장처럼 쓰지 않는다.
- dataset, split, metric, 모델 규모, 학습 조건이 다르면 직접 비교할 수 없음을 밝힌다.
- 원문에 없는 인과관계를 설명 편의를 위해 추가하지 않는다.
- `summary`와 semantic search snippet은 근거가 아니다.

직접 확인하지 못한 해설을 원문 사실과 한 문장에 섞지 않는다. 기존 문서의 해석을 새 자료와 병합할 때도 누가 말한 내용인지 흐려지지 않게 보존한다.
