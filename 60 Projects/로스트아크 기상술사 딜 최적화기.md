# 프로젝트 정의

로스트아크 캐릭터 API와 수기 게임 데이터를 결합해 현재 세팅의 스킬별 피해 지분을 복원하고, 아크패시브·아크그리드·보석·트라이포드·장신구·팔찌 조합 중 기대 딜이 높은 구성을 찾는 개인 최적화 도구다. 단순 스펙 합산기가 아니라 효과가 어느 스킬에 어떤 방식으로 적용되는지 계산 커널에 명시하고, 기준 캐릭터 대비 상대 상승량으로 조합을 비교한다.

# 계산 문제의 구조

초기 탐색 공간은 약 878,850개 조합이었다.

```text
42 × 31 × 15 × 3 × 15 = 878,850
```

각 조합에 대해 스킬별 기준 지분과 후보 설정의 배율을 계산한 뒤 합산한다.

```text
총 상대 딜 = Σ(기준 스킬 지분 × 후보 스킬 배율 / 기준 스킬 배율)
```

피해 배율은 공격력, 주 능력치, 무기 공격력, 추가 피해, 적에게 주는 피해, 치명타 확률·피해, 보석과 트라이포드, 조건부·스킬 전용 효과를 조합한다. 재사용 대기시간이 실제 사용 횟수로 환산되는 효과는 DPS 축에서 별도로 다룬다.

# 입력과 모델링 범위

- 캐릭터 기본 능력치와 장비 정보
- 아크패시브 1~5티어 노드
- 아크그리드 코어와 젬
- 보석 등급·효과와 스킬 연결
- 트라이포드와 스킬별 조건
- 장신구 4부위와 팔찌 옵션
- 공격력·주 능력치·무기 공격력·추가 피해·적에게 주는 피해
- 스킬별 치명타 적중률·치명타 피해·방향성·마나 등 조건부 효과

모든 스킬에 똑같이 곱해지는 범용 효과와 특정 스킬·상태에서만 작동하는 효과를 나눈다. 이 구분이 없으면 전체 공격력 옵션과 특정 스킬 보정이 같은 방식으로 계산되어 최적 조합이 왜곡된다.

# 기준 캐릭터와 스킬 지분 역산

사용자가 입력한 실측 스킬 지분은 이미 현재 보석, 트라이포드, 아크그리드와 특성 효과가 적용된 결과다. 이를 그대로 새 조합에 곱하면 기준 세팅의 효과가 중복된다. 따라서 먼저 기준 캐릭터 설정을 이용해 관측된 지분을 효과 적용 전의 상대 지분으로 역산하고, 각 후보 조합의 효과를 다시 적용한다.

API에서 코어·보석이 없다고 응답하면 이전 입력을 남겨 두지 않고 해당 상태를 비운 뒤 기준 지분을 다시 계산한다. 오래된 캐시가 현재 캐릭터 설정에 섞이는 일을 막기 위한 처리다.

# 성능 구조

초기에는 CPU에서 모든 조합을 순회했으나 WebGPU 경로를 추가했다. GPU 커널의 순수 계산은 약 76ms, 전체 처리도 약 944ms로 확인돼 약 88만 조합을 대화형으로 탐색할 수 있었다. CPU와 WebGPU가 별도의 수식을 가지면 패치가 한쪽에만 반영될 위험이 있으므로, 계산 엔진을 단일 출처로 두고 양쪽 경로가 같은 의미를 따르도록 정리했다.

Excel은 계산 엔진 후보로 검토됐지만 이 규모에서는 WebGPU보다 느리고 수식 유지보수도 어렵다고 판단했다. 대신 결과 내보내기, 수기 검토, 조합 비교 표에는 유용할 수 있다는 결론이었다.

# 중요한 오류 발견과 수정

## 공격·이동 속도 상시 버프

기상술사의 +12% 공격·이동 속도 효과가 처음에는 특정 여우비 상태에서만 적용되는 것으로 모델링됐다. 사용자가 이 효과가 상시 적용된다고 바로잡으면서, 공격·이동 속도 합이 40%를 넘을 때 효율이 달라지는 소닉 계열 진화 계산과 최적 조합이 바뀌었다.

첫 수정 과정에서는 +12%를 기준 상태와 후보에 중복 적용하는 실수도 발생했다. 이 실수를 다시 바로잡으면서, 단 한 줄의 버프 전제가 전체 순위를 바꿀 수 있고 시뮬레이터의 숫자 자체보다 기준 상태와 효과 적용 시점을 검증하는 일이 중요하다는 점이 드러났다.

## 초기 코드 검토에서 드러난 위험

- 기준 세팅이 엔진 안에 하드코딩돼 다른 캐릭터로 바꿀 때 결과가 오염될 수 있었다.
- 치명타 확률 탐색 범위가 10~30으로 제한돼 실제 입력을 충분히 표현하지 못할 수 있었다.
- 공격 속도가 시전 빈도에 미치는 영향이 계산에서 빠져 있었다.
- 모든 스킬이 비방향성으로 등록돼 방향성 보너스 코드가 사실상 작동하지 않았다.
- 재사용 대기시간 감소를 단순 역수로 환산하면 실제 사이클보다 과대평가할 수 있었다.

이 항목들은 계산식이 존재한다는 것과 게임 로직을 정확히 재현한다는 것이 다르다는 점을 보여준다.

# 게임 용어와 효과 데이터 정정

세션에서 사용자가 실제 게임 용어와 효과 관계를 여러 차례 바로잡았다. 예를 들어 진멸 계열의 악마 피해는 독립적인 곱연산 축으로 보아야 하고, 특정 코어 효과는 무력화된 적 조건에서 작동하며, 장신구 슬롯 수도 실제 장비 구조에 맞아야 했다. UI 문구와 툴팁을 게임 내 표현에 가깝게 고치고, 표시 이름과 내부 계산 키를 분리하는 방향으로 정리했다.

# 클래스 확장

기상술사 전용으로 출발했지만 환수사와 배틀마스터 등 다른 클래스까지 확장했다. 클래스마다 다음이 다르다.

- 스킬 목록과 기준 지분
- 치명타·치명타 피해의 조건
- 마나 스킬 여부와 자원 조건
- 보석·트라이포드의 적용 대상
- 아크패시브와 아크그리드의 클래스 전용 효과

따라서 공통 수학 커널과 클래스별 데이터·규칙을 분리하는 방향을 사용했다. 다만 클래스 확장이 빨라질수록 이름만 다른 중복 효과와 클래스 전용 예외가 계산 엔진에 다시 섞일 위험이 있다.

# 검증 상태

엔진·데이터 관련 여러 테스트가 통과했고 CPU와 WebGPU 결과 일치를 확인하는 흐름도 있었다. 한편 `test-api.js`에는 API 캐시와 수기 트라이포드 데이터가 어긋나 이전부터 실패하던 항목 한 건이 기록돼 있다. 따라서 ‘대부분의 테스트 통과’와 ‘최신 라이브 게임 데이터에 대한 완전한 정확성’을 같은 말로 보아서는 안 된다.

# 현재 상태와 남은 과제

2026-08-22까지 클래스 확장, API 입력, UI 용어·툴팁, 계산 성능 개선이 이어졌다. 현재 배포 위치와 최신 게임 패치 반영 여부는 세션 기록만으로 확인되지 않는다.

- 모든 효과에 출처 툴팁·적용 대상·곱연산 그룹·검증 날짜를 붙인다.
- 기준 캐릭터 역산과 후보 적용을 작은 수기 계산 사례로 교차검증한다.
- 쿨다운 감소를 실제 스킬 사이클·시전 시간·자원 제약과 함께 검증한다.
- 클래스별 데이터 팩과 공통 엔진 사이의 계약 테스트를 늘린다.
- 라이브 API 캐시와 수기 데이터의 버전·갱신 시점을 명시한다.
- 최신 패치 뒤 상위 조합 몇 개를 게임 내 허수아비 측정과 비교한다.
