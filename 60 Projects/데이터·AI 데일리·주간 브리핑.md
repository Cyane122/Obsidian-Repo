# 프로젝트 정의

데이터·AI 분야의 채용 공고, 논문, 공식 발표, 오픈소스와 커뮤니티 동향을 정기적으로 조사해 개인 보고서로 축적하는 자동화다. 단순 뉴스 수집기가 아니라 데이터 사이언스 전공 대학생에게 실제로 도움이 될 정보만 추려, 취업 준비와 프로젝트 탐색에 바로 쓸 수 있는 형태로 정리하는 것이 목적이다.

# 시작 배경과 독자

관심 분야의 정보가 채용 사이트, 학술 아카이브, 기업 블로그, GitHub와 커뮤니티에 흩어져 있어 매번 같은 경로를 직접 확인해야 했다. 이 반복 작업을 줄이되, 출처가 불분명한 요약문이나 이미 본 소식이 쌓이는 문제는 피하고자 했다.

주 독자는 데이터 분석·데이터 사이언스·ML/AI 엔지니어링·NLP·LLM·RAG·MLOps 분야를 준비하는 대학생인 본인이다. 따라서 경력직 채용보다 신입·인턴·주니어 공고를 우선하고, 기술 소식도 화제성보다는 학습하거나 개인 프로젝트에 적용할 가치가 있는지를 중심으로 고른다.

# 두 개의 운영 주기

## 데일리 브리핑

매일 한국 시간 정오를 기준으로 새 정보를 조사한다. 컴퓨터가 정각에 꺼져 있을 수 있으므로 이후 주기적 확인에서도 그날 보고서가 아직 없다면 실행할 수 있게 설계했다. 반대로 당일 작업이 이미 끝났다면 몇 번 다시 깨어나더라도 아무 작업도 하지 않는다.

데일리 보고서는 다음 항목을 다룬다.

- 데이터·AI 직군의 신입·인턴·주니어 채용 공고
- arXiv, ACL Anthology, OpenReview와 주요 학회의 새 논문
- AI 기업과 연구기관의 공식 발표, 모델·제품·정책 변화
- Hugging Face, GitHub, Papers with Code에서 발견되는 구현과 모델
- 공식 YouTube 채널의 발표·강연
- Hacker News, r/MachineLearning, r/LocalLLaMA에서 포착되는 관심 신호

## 주간 브리핑

주간판은 같은 웹을 다시 검색하는 두 번째 조사 작업이 아니다. 한 주 동안 저장된 데일리 보고서만 읽고, 반복 등장한 흐름과 중요도가 높아진 항목을 묶어 압축한다. 덕분에 데일리와 주간의 역할이 각각 ‘발견’과 ‘회고’로 나뉘며, 같은 사실을 별도로 조사해 서로 다른 결론을 내는 일을 줄인다.

# 조사와 선별 원칙

## 출처의 위계

공식 채용 페이지, 논문 원문, 기업·연구기관 공지, 공식 저장소를 사실 확인의 기준으로 삼는다. 커뮤니티 글은 무엇이 주목받는지 찾는 탐색 신호로는 쓰지만, 그 글만으로 사실을 확정하지 않는다. 유튜브도 공식 채널과 원 발표자를 우선한다.

## 중복 억제

당일 성공 상태와 보고서 파일을 함께 확인한다. 두 조건이 모두 맞아야 완료로 보고 조사 자체를 건너뛴다. 조사 도중 실패했는데 상태만 성공으로 남는 일을 막기 위해, 보고서 저장까지 끝난 뒤에만 성공 상태를 기록한다. 기존 보고서와 같은 공고·논문·소식은 새 변화가 없는 한 다시 싣지 않는다.

## 유용성 기준

단순히 최신이라는 이유만으로 포함하지 않는다. 채용은 지원 가능성과 역할 적합성을, 논문은 핵심 아이디어와 재현·응용 가능성을, 도구는 실제 프로젝트에 가져다 쓸 수 있는지를 본다. 불확실한 정보는 확정적인 문장으로 바꾸지 않고, 원문 링크와 확인 범위를 남긴다.

# 상태 관리와 실패 방지

```text
정기 실행 확인
→ 한국 날짜 계산
→ 당일 state.json 및 보고서 존재 여부 확인
→ 미완료일 때만 조사
→ 출처 검증·중복 제거·선별
→ 보고서 저장
→ 마지막에 성공 상태 기록
```

`state.json`은 단순 실행 시각이 아니라 해당 날짜의 정상 완료 여부를 판단하는 표식이다. 보고서와 상태 파일을 함께 검사하는 이유는 파일 일부만 만들어진 실패를 성공으로 오인하지 않기 위해서다. 이 구조는 정오 실행을 놓쳤을 때의 보충 실행과 하루 한 번만 조사한다는 멱등성을 동시에 만족시킨다.

# 세션에서 확인된 진행 과정

## 2026-07-19: 데일리 자동화 구축

한국 시간 정오 실행, 당일 중복 방지, 첫 보고서 즉시 생성이 핵심 요구였다. 이후 ‘정오에 PC가 꺼져 있으면 어떻게 하는가’라는 문제가 추가되어, 매시간 상태를 확인하되 이미 성공한 날에는 아무 일도 하지 않는 방식으로 다듬어졌다. 수집처도 일반 검색에 머물지 않고 Hugging Face, GitHub, Papers with Code, 공식 YouTube, Hacker News와 관련 Reddit 커뮤니티까지 넓어졌다.

## 2026-08-23: 주간 회고 분리

주간 브리핑은 새 웹 조사가 아니라 저장된 데일리 보고서의 요약으로 정의됐다. 주간판 역시 이미 정상 생성됐다면 다시 만들지 않는 멱등성을 갖는다. 이 결정으로 ‘매일 발견한 사실’과 ‘한 주 뒤 남길 흐름’이 분리됐다.

## 2026-08-27: 중복 방지 동작 확인

당일 보고서와 성공 상태가 이미 존재하는 것을 확인한 뒤 추가 조사를 하지 않았다. 자동화가 매번 뭔가를 생성하는 것이 아니라, 완료된 날에는 의도적으로 조용히 종료한다는 점이 실제 세션에서 확인됐다.

# 현재 상태

데일리와 주간 자동화가 모두 존재하고, 데일리의 보충 실행 및 중복 방지 흐름도 확인됐다. 다만 세션 기록은 자동화의 운영 로직을 보여줄 뿐, 생성된 정보가 실제 지원·논문 읽기·프로젝트 착수로 얼마나 이어졌는지는 아직 측정하지 않는다.

# 남은 과제

- 오래된 원문·상태 파일을 어느 기간까지 보존할지 정한다.
- 관심 없는 직무와 반복적으로 제외되는 출처를 학습할 수 있는 피드백 구조를 검토한다.
- ‘저장함’, ‘읽음’, ‘지원함’, ‘프로젝트에 적용함’ 같은 후속 행동을 연결해 선별 품질을 평가한다.
- 출처 사이트 구조가 바뀌거나 접근이 막혔을 때 보고서 전체가 실패하지 않도록 수집처별 실패를 분리한다.
