# 주요 화면

## [[레이드 기록 (Ark Grid Core Log)|레이드 기록]]

캐릭터마다 참여 가능한 레이드와 난이도를 보여주고, 클리어 여부와 등급별 코어 수를 기록한다. 코어를 하나라도 추가하면 클리어가 자동으로 체크된다. 반대로 코어가 0개였던 클리어도 표본이므로, 수량을 올리지 않고 클리어만 표시할 수 있다.

초기 여섯 캐릭터는 기상술사, 환수사, 소울이터, 발키리, 배틀마스터, 도화가였다. 이후 API 동기화에서는 대표 캐릭터를 기준으로 원정대 캐릭터 15명을 조회한 뒤, 기록 대상으로 지정한 클래스마다 아이템 레벨이 가장 높은 캐릭터를 고르는 방식으로 바뀌었다.

## [[천장 기록 (Ark Grid Core Log)|천장 기록]]

정가로 얻은 코어는 주간 레이드 드랍과 획득 규칙이 다르므로 별도 화면에 누적한다. 특정 주차에 묶지 않고 시도할 때마다 결과 등급을 한 건씩 기록하며, 레이드 통계에 섞지 않는다.

## [[확률 추정 (Ark Grid Core Log)|확률 추정]]

등급별 코어 수를 전체 획득 코어 수로 나눠 분포를 보여준다. 처음 제시됐던 ‘클리어당 한 개 이상 획득한 비율’은 사용자의 정정으로 폐기됐다.

```text
등급별 추정 비율 = 해당 등급 코어 수 / 전체 획득 코어 수 × 100
```

클리어 횟수는 확률의 분모가 아니라 표본 규모를 보여주는 수치다. 기록이 없거나 정의할 수 없는 값은 0%로 오해되지 않도록 `—`로 표시하며, 1720 이상 구간의 영웅 코어 표시도 이 예외를 따른다.

# 레이드·골드 데이터

사이트에 들어간 레이드·난이도 조합은 13개까지 늘었다. 캐릭터 아이템 레벨로 입장 가능한 난이도를 걸러내고, 가장 높은 난이도를 기본 선택한다. 기록 카드에는 다음 값이 함께 들어간다.

- 레이드와 난이도
- 클리어 여부
- 전설·유물·고대·영웅 코어 획득 수
- 기본 획득 골드
- 더보기 비용
- 획득 골드에서 더보기 비용을 뺀 순골드

대성당처럼 귀속 골드가 포함되는 레이드는 현금성 골드와 구분해 표시한다. 주간 골드 합계에는 순골드가 높은 상위 세 레이드만 반영하지만, 네 번째 이후 레이드의 코어 기록은 버리지 않는다. 골드 제한과 드랍 통계의 표본 범위가 서로 다른 셈이다.

# [[원정대 동기화 (Ark Grid Core Log)|원정대 동기화]]

대표 캐릭터를 기준으로 로스트아크 API에서 원정대 캐릭터를 읽어 온다. 각 지정 클래스에서 아이템 레벨이 가장 높은 캐릭터를 선택하고, 레이드 자격과 기본 난이도에 반영한다.

API JWT는 서버 비밀값으로 두고 브라우저에 보내지 않는다. 응답에는 `no-store`를 적용하고 별도 쿠키도 만들지 않았다. 캐릭터 정보만 API로 갱신하며, 사용자가 입력한 코어 기록은 브라우저 로컬 저장소에 남는다.

# 주간 경계와 로컬 저장

주차는 한국 시간 수요일 오전 6시에 바뀐다. 달력상 월요일이나 자정이 아니라 실제 게임 초기화 시점을 기준으로 삼는다. 페이지를 열 때 현재 한국 시간을 계산해 경계를 지났으면 새 주차 입력 상태로 전환하되, 과거 누적 통계와 천장 기록은 유지한다.

서버 계정이나 데이터베이스 없이 브라우저 저장소에 즉시 저장하므로 입력은 빠르다. 대신 다음 한계가 있다.

- 다른 PC나 휴대전화와 기록이 자동으로 이어지지 않는다.
- 브라우저 데이터를 지우면 기록을 잃을 수 있다.
- API로 원정대 명단을 갱신해도 로컬 코어 기록이 서버에 백업되는 것은 아니다.
- 같은 주소를 다른 사람이 열어도 사용자의 기존 기록은 따라가지 않는다.

# 외형과 사용성

모바일에서 `+`와 `−`를 빠르게 누르는 사용성을 우선했다. Pretendard 글꼴과 클래스 로고를 사용하고, 캐릭터별 카드에서 현재 주의 진행 상황과 누적값을 곧바로 확인하게 했다. 스프레드시트처럼 많은 셀을 편집하기보다 실제 플레이 직후 짧게 기록하는 흐름에 맞춘 화면이다.
