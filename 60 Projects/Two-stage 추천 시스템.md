# 프로젝트 정의

MovieLens-1M의 사용자–영화 상호작용을 이용해 후보를 넓게 찾고, 학습형 랭커가 상위 순서를 다시 결정하는 Two-stage 추천 시스템 과제다. 추천 결과의 단일 점수만 높이는 것이 아니라 후보 생성기의 회수율, 재랭커의 상단 정렬 능력, 인기 편향과 사용자별 편차를 나누어 관찰하는 데 초점을 뒀다.

# 문제 설정

한 번에 모든 사용자–영화 쌍을 정교한 모델로 평가하면 비용이 크다. 따라서 첫 단계는 실제 정답이 포함될 가능성이 높은 작은 후보군을 빠르게 만들고, 두 번째 단계가 더 많은 특징을 사용해 그 후보군만 재정렬한다.

```text
사용자별 과거 상호작용
→ ALS·최근 인기·전체 인기 후보 생성
→ 후보 합치기와 중복 제거
→ 사용자·아이템·교차 특징 계산
→ LightGBM 재랭킹
→ nDCG·Recall·Coverage·세그먼트 평가
```

# 데이터 분할에서 내린 핵심 판단

MovieLens-1M 사용자는 실제 서비스처럼 수개월에 걸쳐 영화를 소비한 기록이라기보다, 짧은 시간 안에 과거 평점을 몰아서 입력한 경우가 많다. 그래서 전역 시각 하나로 train/test를 자르면 평가 시점에 충분한 이력이 있는 사용자가 크게 줄어든다.

기본 평가는 각 사용자 안에서 시간순으로 history, rank-label, test 구간을 나누는 per-user temporal split을 사용했다. 강의식 global split도 비교 경로로 남겨 두어, 분할 선택이 모델 성능과 평가 대상 사용자 수에 어떤 영향을 주는지 확인했다. 이 프로젝트에서 분할은 단순 전처리 옵션이 아니라 추천 문제 자체를 어떻게 정의하는지에 관한 결정이었다.

# 1단계: 후보 생성

## ALS 후보

암시적 피드백 행렬에 ALS를 적용해 개인화 후보를 만든다. 초기의 큰 잠재 차원과 높은 confidence scaling이 항상 유리하지 않았다. 데이터와 아이템 규모에 맞춰 factors를 96에서 32로, alpha를 40에서 10으로 낮췄을 때 ALS 단독 평가가 개선됐다.

- nDCG@10: 약 `0.0477 → 0.0581`
- Recall@100: 약 `0.287 → 0.328`

## 인기 기반 보완 후보

ALS가 놓칠 수 있는 항목을 보완하기 위해 전체 인기와 최근 인기 후보를 섞었다. 최근 인기 계산의 기준 시각을 데이터 최댓값으로 단순 고정하면 일부 장기 활동 사용자의 시각에 끌려 최근 창에 들어오는 상호작용이 529개로 줄었다. 분위수 기반 스냅샷으로 바꾸자 같은 창에서 5,345개를 사용할 수 있어 최근 인기 신호가 훨씬 안정됐다.

## 후보 수와 상단 품질의 충돌

모든 사용자에게 인기 아이템을 채워 최소 300개 후보를 강제하면 정답 포함률과 oracle 상한은 올라갔다. 그러나 실제 nDCG@10은 약 `0.0667 → 0.0646`으로 낮아졌다. 후보가 많다는 사실 자체보다 재랭커가 구분하기 어려운 잡음 후보가 얼마나 섞이는지가 중요하다는 결과다. 따라서 이 옵션은 실험 경로로 남기되 기본값에서는 껐다.

# 2단계: 재랭킹

LightGBM 기반 랭커가 각 후보의 최종 순서를 학습한다. 특징은 단일 점수에 의존하지 않고 다음 축을 함께 사용한다.

- 사용자 활동량과 선호 통계
- 영화의 전체·최근 인기도
- ALS 점수와 후보 출처
- 사용자와 아이템의 장르·활동 특성
- 후보 점수와 인기도 사이의 교차 특징
- 사용자의 데이터가 풍부한지 희소한지를 나타내는 세그먼트 특징

후보가 어디서 왔는지와 사용자의 이력 수준을 함께 보게 함으로써, 같은 인기 점수라도 신규·희소 사용자와 활동량이 많은 사용자에게 다르게 해석할 수 있게 했다.

# 평가 설계

## 지표

- `Recall@K`: 정답이 후보 또는 추천 상위 K 안에 들어왔는지 본다.
- `nDCG@K`: 정답을 찾았을 뿐 아니라 얼마나 위에 배치했는지 본다.
- `Coverage`: 소수 인기 영화만 반복 추천하지 않는지 확인한다.
- 후보 oracle: 현재 후보군 안에서 재랭커가 이론상 달성할 수 있는 상한을 본다.

## 진단 단위

전체 평균만 보지 않고 사용자 활동량과 희소성에 따른 세그먼트 결과를 확인했다. 후보 생성 Recall이 낮으면 랭커 개선만으로 해결할 수 없고, 후보 Recall은 높은데 nDCG가 낮으면 재랭킹 특징이나 학습 설정을 의심하는 식으로 두 단계를 분리해 진단했다.

# 세션에서 확인된 결과와 산출물

- 데이터 적재부터 분할, 후보 생성, 특징 계산, 재랭킹, 평가까지 전체 파이프라인을 구성했다.
- per-user와 global temporal split을 비교 실행할 수 있게 했다.
- ALS 하이퍼파라미터와 최근 인기 스냅샷 기준을 실험으로 수정했다.
- 후보 강제 확장의 Recall–nDCG 절충을 확인하고 기본 동작에서 제외했다.
- 스모크 테스트 7개가 통과했다.
- 재현 방법과 설계 판단을 README에 정리했다.

# 해석과 한계

이 과제의 가장 큰 교훈은 ‘좋은 랭커’만으로 Two-stage 추천이 완성되지 않는다는 점이다. 후보군에 정답이 없으면 재랭커는 복구할 수 없고, 후보군을 무작정 넓히면 상단 순위가 오히려 나빠질 수 있다. 또한 MovieLens-1M의 타임스탬프는 실제 연속 소비 시계열과 다르므로, 오프라인 시간 분할 결과를 실서비스의 미래 예측 성능으로 그대로 해석해서는 안 된다.
