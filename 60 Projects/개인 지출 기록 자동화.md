# 프로젝트 정의

안드로이드에 도착한 결제 알림을 Tasker가 수집·정규화해 Gmail로 전달하고, 이후 AI가 Google Sheets 거래 장부에 반영하도록 설계한 개인 자동화다. 금융기관에 직접 로그인하거나 거래내역을 긁어오는 대신 이미 사용자 휴대전화에 표시된 알림만 입력으로 삼는다.

# 해결하려는 문제

소액 결제를 매번 장부에 옮기는 일은 단순하지만 누락되기 쉽다. 금융사별 API나 별도 서버를 도입하면 구현과 보안 부담이 커진다. 첫 단계에서는 익숙한 도구인 Tasker, Gmail, Google Sheets를 연결해 유지할 수 있는 가장 작은 파이프라인을 만드는 것을 우선했다.

```text
금융 앱 결제 알림
→ Tasker가 앱·제목·본문·수신 시각 수집
→ 앱별 파서와 fallback 정규화
→ 구조화된 Gmail 메시지 전송
→ AI가 검토·중복 판단
→ Google Sheets 거래 장부 반영
```

# 의도적으로 하지 않는 일

이 프로젝트의 자동화 범위는 휴대전화 알림 이후로 제한된다.

- 금융 사이트나 앱 화면을 스크래핑하지 않는다.
- 로그인 자동화, 인증 우회, 접근성 기능을 이용한 화면 탈취를 하지 않는다.
- 비밀번호, 세션, 토큰, 카드 인증 정보를 수집하거나 저장하지 않는다.
- 첫 마일스톤에서 별도 서버·데이터베이스·Apps Script를 필수 구성으로 두지 않는다.

이 경계는 단순한 구현 편의가 아니라 민감한 금융정보의 공격 표면을 좁히기 위한 설계 원칙이다.

# 알림 파싱

## 지원 경로

Naver Pay, Toss Pay, 카드 앱용 파서를 두고, 알려지지 않은 앱이나 문구에는 fallback 파서를 적용한다. 각 파서는 금액, 거래 시각, 결제·취소·환불 같은 이벤트 유형, 가맹점으로 보이는 텍스트를 추출한다.

## 실패를 숨기지 않는 구조

알림 문구가 바뀌거나 필드가 모호하더라도 메시지 자체를 버리지 않는다. 원문과 출처 앱, 수신 시각을 보존하고 확정하지 못한 값은 `UNKNOWN`으로 남긴다. 잘못 추측해 정리한 데이터보다 나중에 사람이 감사할 수 있는 불완전한 데이터를 우선한다.

# 중복 처리 원칙

결제 하나가 카드 앱, 간편결제 앱 등 여러 출처에서 각각 알려질 수 있다. 두 알림이 같은 거래인지 확정하기 어렵기 때문에, 서로 다른 앱에서 온 비슷한 알림을 자동으로 삭제하지 않는다. 장부 단계에서 중복 후보로 표시하거나 사람이 확인할 수 있도록 원본을 남긴다.

반면 Tasker 재시도나 시스템 재알림으로 같은 이벤트가 반복 전송되는 것은 억제해야 한다. 이를 위해 정규화된 필드로 결정론적 이벤트 ID를 만들고 최근 20개 ID 안에서 같은 이벤트의 재전송을 막는다. 이 창은 무한한 거래 중복 제거기가 아니라 짧은 재시도 폭주를 차단하는 장치다. 같은 금액을 연속 결제한 정상 거래가 별개 이벤트로 남도록 수신 시각과 원문 맥락을 함께 사용한다.

# 구조화된 메시지의 역할

Gmail은 단순 알림 전달뿐 아니라 첫 단계의 감사 로그 역할을 한다. 원문과 파싱 결과가 함께 남으므로 AI가 후속 단계에서 다음을 판단할 수 있다.

- 파싱 결과를 그대로 장부에 넣어도 되는가
- 취소·환불을 기존 거래와 연결할 수 있는가
- 다른 앱의 알림과 같은 거래일 가능성이 있는가
- 정보가 부족해 사람 확인이 필요한가

결정론적 파서가 확실한 형식을 만들고, AI는 애매한 의미 판단을 맡는 식으로 역할을 나눈다.

# 구현된 첫 마일스톤

- Naver Pay, Toss Pay, 카드 앱과 범용 fallback 파서
- 금액·시간·이벤트 유형 정규화
- 원본 알림과 불확실한 필드 보존
- 결정론적 이벤트 ID와 최근 이벤트 재전송 억제
- Tasker에서 가져올 수 있는 프로젝트 자산
- 휴대전화 설정과 Gmail 연결 절차를 설명한 가이드
- 결제·취소·환불·중복·파싱 실패를 다루는 테스트 52개

세션에서 52개 검증이 모두 통과해 코드 수준의 첫 마일스톤은 완료됐다. 다만 실제 금융 앱의 최신 알림 문구와 Android 권한 환경에서 끝까지 동작하는지는 휴대전화 확인이 필요하다.

# 완료 범위와 미완료 범위

## 확인된 완료

`결제 알림 → Tasker → 구조화된 Gmail` 구간과 관련 테스트·설정 가이드.

## 목표로만 확인됨

`Gmail → AI 검토 → Google Sheets 장부` 구간. 어떤 열 구조를 쓸지, AI가 바로 쓰기 권한을 가질지, 중복·환불 후보를 사람에게 먼저 보여줄지는 아직 확정된 구현 기록이 없다.

# 다음 단계

- 실제 휴대전화에서 앱별 알림 샘플을 모아 파서 회귀 테스트에 추가한다.
- Google Sheets의 거래 ID, 원본 메시지 ID, 결제·취소 연결 필드를 정의한다.
- 확실한 거래만 자동 반영하고 애매한 건 검토함으로 보내는 승인 경계를 정한다.
- 개인정보가 포함된 Gmail 원문과 장부의 보존 기간·접근 권한을 정한다.
- 앱 문구 변경으로 `UNKNOWN` 비율이 늘어나는지 알 수 있는 점검 방법을 둔다.
