## 2. 4강 — Text Representation
### 2.1 Bag-of-Words (BoW)
- 텍스트를 **단어별 등장 횟수**(Count), 등장 여부(Binary), 또는 정규화된 빈도 등으로 표현한다.
- 문서-단어 행렬(Document–Term Matrix, DTM)은 행이 문서, 열이 단어인 형태로 만들 수 있다.
- **장점:** 단순하고 해석하기 쉽다.
- **한계:** 기본 unigram BoW는 단어 **순서와 의미적 관계**를 잃고, 어휘 수가 많으면 차원이 커지고 희소해진다.
- 예시: `dog bites man`과 `man bites dog`는 unigram BoW가 동일하다. **Bigram**은 연속된 두 단어를 보므로 일부 순서 정보가 살아난다.

> **Expected:** What is the main limitation of Bag-of-Words?
> **Answer:** *Bag-of-Words ignores word order and does not directly capture semantic relationships between words.*

### 2.2 TF, DF, IDF, TF-IDF — '왜'를 우선 이해

| 개념                               | 의미                           | 직관                               |
| -------------------------------- | ---------------------------- | -------------------------------- |
| TF (Term Frequency)              | 단어가 **특정 문서**에서 얼마나 자주 등장하는지 | 그 문서 내 중요도                       |
| DF (Document Frequency)          | 단어가 등장한 **문서의 수**            | 전체 말뭉치에서 얼마나 널리 나타나는지            |
| IDF (Inverse Document Frequency) | 흔한 단어를 낮게, 드문 단어를 높게 평가      | 문서 구별력                           |
| TF-IDF                           | TF와 IDF를 결합                  | 해당 문서에서 자주 등장하지만 전체적으로는 드문 단어 강조 |

기본 개념식(수업에서 로그 밑이나 smoothing 변형 가능):

$$
TF(t,d)=\frac{\mathrm{count}(t,d)}{|d|},\qquad
IDF(t)=\log\frac{N}{df(t)},\qquad
TF\text{-}IDF(t,d)=TF(t,d)\times IDF(t)
$$

- **DF가 증가하면 IDF는 감소한다.** 모든 문서에 나오는 단어라면 기본 식의 IDF는 0이다.
- **TF가 높아도 IDF가 낮으면** TF-IDF는 크지 않을 수 있다.
- 예시: `the`는 매우 흔하므로 특정 문서를 구별하는 데 유용하지 않을 수 있다.

> **Expected:** Why do we use IDF instead of only TF?
> **Answer:** *IDF down-weights terms that occur in many documents and gives more weight to rare, discriminative terms.*
> **Expected:** Why is TF-IDF more useful than raw word counts?
> **Answer:** *TF-IDF considers both a term's frequency in a document and its rarity across the corpus.*

### 2.3 One-hot vs Dense Embedding

- **One-hot:** 어휘 수만큼 긴 벡터에서 자기 위치 하나만 1. 대부분 0인 **희소 벡터**이며, 단어 간 의미적 유사성을 표현하지 못한다.
- **Dense embedding:** 학습된 비교적 낮은 차원의 실수 벡터. 의미적·통계적 관계를 반영할 수 있다.
- 주의: Word2Vec·GloVe 같은 전통적인 **정적 embedding**은 같은 단어에 문맥마다 자동으로 다른 벡터를 주는 방식이 아니다.

> **Expected:** Why are word embeddings useful compared with one-hot vectors?
> **Answer:** *Dense embeddings use lower-dimensional vectors and can represent similarities between words, unlike one-hot vectors.*

### 2.4 Word2Vec — 방향을 바꾸지 말 것

```text
Skip-gram : center word  ──> surrounding/context words
CBOW      : context words ──> center word
```

예시 `small birds sing loudly`, 중심 단어 `sing`, 문맥 창 1:
- **Skip-gram:** 입력 `sing` → 예측 대상 `birds`, `loudly`
- **CBOW:** 입력 `birds`, `loudly` → 예측 대상 `sing`
- 두 방식 모두 문맥 창을 활용하고, 예측 목적을 통해 단어 벡터를 학습한다.

> **Expected:** Compare Skip-gram and CBOW.
> **Answer:** *Skip-gram predicts surrounding words from a center word, whereas CBOW predicts a center word from surrounding words.*

### 2.5 GloVe — Global = 말뭉치 전체 통계

- **동시출현 행렬(co-occurrence matrix)**의 원소 \(X_{ij}\)는 보통 단어 \(i\)의 문맥 창에 단어 \(j\)가 등장한 누적 횟수를 나타낸다(창과 가중치 정의에 따라 세부 계산은 달라짐).
- GloVe는 이런 **집계된 전역 동시출현 통계**를 사용하여 단어 벡터를 학습한다.
- Word2Vec Skip-gram은 중심 단어에서 주변 단어를 예측하는 방식으로 학습한다.
- GloVe의 `Global`은 **긴 문장을 더 잘 이해한다는 보장**이 아니다. GloVe도 동시출현을 수집할 때 문맥 창을 사용한다.

> **Expected:** How does GloVe differ from Word2Vec?
> **Answer:** *GloVe learns from global word co-occurrence statistics, while Word2Vec learns through local context prediction.*

### 2.6 FastText / Doc2Vec

- **FastText:** 단어를 문자 N-gram(subword)으로 나누어 활용한다. 학습 중 등장하지 않은 단어라도 알려진 subword를 통해 벡터를 만들 수 있는 경우가 있어 **OOV(Out-of-Vocabulary)** 대응에 유리하다.
- **Doc2Vec:** 단어가 아닌 **문서 전체의 벡터 표현**을 학습한다.

> **Expected:** Why can FastText handle some unseen words?
> **Answer:** *FastText uses character n-grams, allowing it to build representations from known subword units.*

## 3. 3강 — Sentiment Analysis with R
### 3.1 감성 사전 구별

| 감성 사전            | 출력·특징                                        | 시험에서 주의할 점                  |
| ---------------- | -------------------------------------------- | --------------------------- |
| **AFINN**        | 단어에 음수~양수 **감성 강도** 점수(흔히 -5~+5)             | 반복 단어는 단순 합산에서 여러 번 반영됨     |
| **Bing Liu**     | Positive / Negative 이진 범주                    | AFINN처럼 강도 점수를 제공하는 사전이 아님  |
| **NRC**          | Joy, Fear, Trust 등 감정 범주 및 Positive/Negative | **한 단어가 여러 범주**에 속할 수 있음    |
| **SentiWordNet** | 특정 **WordNet 의미(synset)**별 긍정·부정·객관성 점수      | 같은 표기라도 의미가 다르면 점수가 다를 수 있음 |

SentiWordNet의 기본 관계: `PosScore + NegScore + ObjScore = 1`
예: Pos = 0.25, Neg = 0.50이라면 Obj = **0.25**. 단, 다른 의미의 같은 단어가 **동일한 점수**를 가져야 하는 것은 아니다.

> **Expected:** How does NRC differ from AFINN?
> **Answer:** *NRC assigns emotion categories, and a word can belong to multiple categories. AFINN provides numerical sentiment intensity scores.*

### 3.2 Lexicon-based Sentiment Analysis의 한계

- **Negation:** `good` vs `not good`, `bad` vs `not bad`.
- **Sarcasm:** 말 그대로의 긍·부정 단어가 실제 화자의 의도와 반대일 수 있음.
- **Domain dependence:** `unpredictable`이 영화에서는 호평, 기계 동작에서는 불만일 수 있음.
- **Word sense:** 단어 의미가 달라지면 감성도 달라질 수 있음.
- **단순 합산의 한계:** 점수의 상쇄가 문장 전체 의미를 정확히 나타낸다는 보장이 없음.

**부정어 처리의 올바른 순서:**

```text
Original: not good
Keep "not" during preprocessing → bigram "not good" 생성 가능
Remove "not" first       → "good"만 남아 bigram으로도 부정 정보 복구 불가
```

주의: `not`을 **보존하는 것만으로** 단순 감성 사전 합산이 자동으로 부정의 의미를 이해하는 건 아니다. Bigram 특징이나 부정 처리 규칙 등도 필요하다.

> **Expected:** Why can stopword removal harm sentiment analysis?
> **Answer:** *Removing negation words such as "not" can reverse or erase sentiment information. We should preserve them and use features such as "not good".*

### 3.3 R 코드: 손코딩보다 '각 줄의 의미 + 표의 변화'

```r
result <- tokens %>%
  inner_join(nrc, by = "word") %>%
  count(id, sentiment) %>%
  pivot_wider(
    names_from = sentiment,
    values_from = n,
    values_fill = 0
  )
```

1. `inner_join(nrc, by = "word")`: 토큰과 NRC의 단어가 **일치하는 행만 결합**. 한 토큰이 joy와 positive 두 범주에 속하면 결과 **두 행**이 생길 수 있다.
2. `count(id, sentiment)`: 문서와 감성 범주별 빈도 집계. **결과 열 이름은 `id`, `sentiment`, `n`**.
3. `pivot_wider(names_from = sentiment, values_from = n)`: `sentiment`의 값들(joy 등)을 각각 **열 이름**으로 만들고 빈도 `n`을 셀 값으로 넣는다.
4. `values_fill = 0`: 어떤 문서에 해당 감성 범주가 없다면 0으로 채운다.

**예시 데이터**

`tokens`:

| id | word |
|---:|---|
| 1 | bright |
| 1 | scary |
| 2 | bright |
| 2 | bright |

`nrc`:

| word | sentiment |
|---|---|
| bright | joy |
| bright | positive |
| scary | fear |
| scary | negative |

`inner_join` 후에는 문서 1의 2개 토큰이 총 4행으로 매칭된다. 문서 2의 `bright` 2회는 각각 2개 감정 범주에 매칭돼 4행이 된다.

최종 결과:

| id | fear | joy | negative | positive |
|---:|---:|---:|---:|---:|
| 1 | 1 | 1 | 1 | 1 |
| 2 | 0 | 2 | 0 | 2 |

> **Expected:** Why can `inner_join()` increase the number of rows with NRC?
> **Answer:** *A single word may match multiple emotion categories, so one token can produce multiple joined rows.*
> **Expected:** What does `pivot_wider()` do here?
> **Answer:** *It converts sentiment categories into columns and fills them with their counts for each document.*

### 3.4 R 주요 함수 — 목적만 바로 떠올리기

| 함수 | 역할 |
|---|---|
| `unnest_tokens(word, text)` | 텍스트를 단어 등 토큰 단위로 풀기 |
| `get_stopwords()` | 불용어 목록 불러오기 |
| `anti_join()` | 다른 표에서 일치하는 행을 **제외** (불용어 제거에 사용) |
| `inner_join()` | 두 표의 키가 **일치하는 행을 결합** |
| `group_by()` | 그룹 기준 지정 |
| `summarise()` | 그룹별 집계 결과 산출 |
| `count(id, word)` | 문서-단어별 빈도 집계 (`n` 생성) |
| `mutate()` | 기존 행에 새 열 계산·추가 |
| `pivot_wider()` | 범주 값들을 열로 전개 |

**잘 틀리는 것:** `count(id, sentiment)` 이후에는 원래의 `word` 열이 없어지고 빈도 열이 `n`이라는 점. 코드를 외우기보다 **각 줄 다음에 어떤 열이 남는지** 확인한다.

## 4. 2강 — Levels of Natural Language

### 4.1 언어 분석 단계

| 단계 | 다루는 것 | 예시·구별 포인트 |
|---|---|---|
| **Phonetics** | 물리적 음성 | 실제 발음 소리 |
| **Phonology** | 언어의 소리 체계 | 음운·발음 규칙 |
| **Morphology** | 단어 내부 형태소 구조 | `un + happy + ness` |
| **Syntax** | 문장 구조·문법적 결합 | `I saw the man with a telescope`의 구조적 중의성 |
| **Semantics** | 단어·문장의 의미 | `bank`의 뜻, 문장의 문자적 의미 |
| **Pragmatics** | 발화 상황·화자의 의도 | “방이 어둡다” = 불을 켜 달라는 간접 요청 가능 |
| **Discourse** | 문장 간 연결·맥락 | 대명사가 이전 문장의 누구를 가리키는지 |

**Morphology와 WSD는 다르다.** `bank`가 금융기관인지 강둑인지 판단하는 일은 **Word Sense Disambiguation(WSD)**이다. 단어의 접사·어근을 자르는 일이 아니다.

> **Expected:** What is the difference between semantics and pragmatics?
> **Answer:** *Semantics studies literal meaning, while pragmatics studies intended meaning in context.*
> **Expected:** What is Word Sense Disambiguation?
> **Answer:** *It identifies the intended meaning of an ambiguous word using its context.*

### 4.2 전처리 방법

| 방법 | 원리 | 주의할 점 |
|---|---|---|
| **Tokenization** | 텍스트를 단어·문장 등의 단위로 나눔 | 구두점, 축약형을 어떻게 나눌지는 규칙에 따라 다름 |
| **Stopword removal** | `the`, `is` 같은 흔한 단어를 제외하기도 함 | 감성 분석의 `not` 등은 보존하는 편이 유리할 수 있음 |
| **Stemming** | 규칙·휴리스틱으로 접사 제거 | `studies → studi`처럼 **비사전형** 가능 |
| **Lemmatization** | 품사 등 언어학적 정보로 사전형(lemma) 찾기 | `studies → study`, `am → be` |
| **POS tagging** | 명사·동사 등 품사 결정 | 문맥에 따라 단어의 품사가 달라질 수 있음 |
| **N-gram** | 연속된 N개 토큰 묶기 | Unigram은 순서 제한, Bigram은 인접 관계 일부 보존 |

문장이 토큰 \(m\)개이고 연속된 N-gram의 길이가 \(n\)이면 개수는 \(m-n+1\) (단, \(n\le m\)). 숫자 암기보다 **연속된 창을 한 칸씩 이동한다**는 원리를 기억하자.

> **Expected:** Why can stemming produce non-dictionary words?
> **Answer:** *Stemming removes affixes using heuristic rules without guaranteeing a valid dictionary form.*
> **Expected:** How does lemmatization differ from stemming?
> **Answer:** *Lemmatization uses linguistic information to find dictionary forms, whereas stemming mainly applies affix-removal rules.*

## 5. 1강 — Introduction to Text Mining

### 5.1 Text Mining과 관련 분야

- **Text Mining:** 방대한 텍스트에서 패턴·지식·유용한 정보 발견.
- **Information Retrieval (IR):** 조건에 맞는 **기존 문서 검색**.
- **Information Extraction (IE):** 문서에서 **개체, 관계, 사실 등을 구조화하여 추출**.
- **NLP:** 인간 언어를 컴퓨터가 처리하도록 하는 기술·방법 전반.
- **Text Classification:** 정해진 범주로 문서를 분류하는 지도학습 작업.
- **Text Clustering:** 사전 라벨 없이 유사한 문서를 묶는 비지도학습 작업.
- **Topic Modeling:** 문서 집합의 숨겨진 토픽 구조 발견. LDA에서는 **토픽 = 단어 확률분포**, **문서 = 토픽 확률분포**로 생각할 수 있다.
- **Summarization:** 문서의 핵심을 요약. Extractive는 원문 구절 선택, Abstractive는 새 문장 생성.

예: 불만 이메일에서 `battery` 포함 메일 찾기(IR) → 제품명·불만 유형 뽑기(IE) → 전체 불만의 반복 패턴 파악(Text Mining).

> **Expected:** How does text classification differ from clustering?
> **Answer:** *Classification assigns predefined labels using labeled examples, while clustering groups similar documents without predefined labels.*
> **Expected:** How does topic modeling differ from clustering?
> **Answer:** *Clustering groups similar documents, whereas topic modeling discovers latent topics and can represent each document as a mixture of topics.*

### 5.2 전체 파이프라인

```text
Raw text → Preprocessing → Numerical representation → Modeling/analysis → Interpretation
              │                   │
         tokenize, clean       BoW, TF-IDF,
         stopwords, lemma      embeddings
```

**왜 전처리하나?** 잡음과 불필요한 변형을 줄이고, 분석에 적합한 입력을 만들기 위해서다. 다만 어떤 정보를 지울지는 작업 목적에 따라 달라진다.

> **Expected:** Why is text preprocessing important?
> **Answer:** *Preprocessing reduces noise and converts raw text into more consistent units for analysis. It should preserve information important to the task.*

## 6. 이전 모의고사에서 실제로 드러난 주의점

| 반복 실수·위험 | 시험장에서 점검할 것 |
|---|---|
| Skip-gram과 CBOW 방향 뒤집기 | **Skip-gram = Center→Context / CBOW = Context→Center**를 먼저 확인 |
| GloVe의 Global 오해 | **전역 동시출현 통계**이지 장문 이해 보장이 아님 |
| NRC를 단어당 한 범주로 간주 | 한 단어가 여러 감정 범주에 매칭 가능 |
| R `count()` 이후 열 이름 혼동 | `count(id, sentiment)` → `id`, `sentiment`, `n` |
| Stopword와 Bigram 관계 | `not`을 **보존한 다음** bigram 사용. 지운 정보는 복구 불가 |
| Topic Modeling을 시각화라고만 설명 | **잠재 토픽 발견**, 토픽-단어 및 문서-토픽 확률분포 |
| Semantics/WSD와 Morphology 혼동 | 뜻 구분=WSD, 형태소 분석=Morphology |
| 객관식에서 일부만 맞는 선택지 고르기 | **선택지의 모든 절이 참인지** 확인 |
| 서술형 답안의 요구 누락 | Definition → Why/Difference → Example/Consequence |
| 계산에서 수치·반올림 누락 | 계산이 나오면 최종 숫자·단위·반올림 자릿수 확인 |

## 7. 내일 읽고 바로 확인할 자기점검 15문항

정답은 위 내용에 모두 있으니, **각 질문에 영어 1~2문장으로 답할 수 있으면 체크**하자.

- [ ] 1. Why do we use IDF instead of only TF?
- [ ] 2. What information does unigram BoW fail to capture?
- [ ] 3. Why are dense embeddings useful compared with one-hot vectors?
- [ ] 4. How do Skip-gram and CBOW differ?
- [ ] 5. What does the “global” in GloVe refer to?
- [ ] 6. How does GloVe differ from Word2Vec?
- [ ] 7. Why is FastText helpful for some OOV words?
- [ ] 8. How do AFINN, Bing, NRC, and SentiWordNet differ?
- [ ] 9. Why can an NRC join create more rows than the input token table?
- [ ] 10. What happens to the columns after `count(id, sentiment)`?
- [ ] 11. Why is removing “not” risky in sentiment analysis?
- [ ] 12. What is the difference between stemming and lemmatization?
- [ ] 13. How do semantics and pragmatics differ?
- [ ] 14. How do classification, clustering, and topic modeling differ?
- [ ] 15. What is the difference between information retrieval and information extraction?

### 시험장에서 영어 단답형 쓰는 법

1. **What:** 정의를 한 문장으로.
2. **Why/Compare:** 핵심 작동 원리나 차이를 한 문장으로.
3. **Example/Consequence:** 문제에서 요구할 때만 짧은 예시 추가.

길게 설명하려다 개념을 흐리기보다, **정확한 용어를 포함한 1~3문장**이 유리하다.
